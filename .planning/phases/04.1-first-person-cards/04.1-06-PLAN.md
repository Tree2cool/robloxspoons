<objective>
What a card physically is, and the privacy rule that constrains it.

**D-45 is the largest new risk in this phase and it is not a style choice.** Non-negotiable rule 3
says nothing hidden may be a replicated Instance, and CARD-13 says a player sees their own hand and
only the pile *depths* of others. The Phase 4 overlay was private for free, because a `ScreenGui` is
client-side by construction. **3D objects are not.** A card rendered as a server-side part in a
player's hands is a replicated Instance carrying a hidden rank, readable by any cheat client in the
game.

So the design has three layers, and each one assumes the previous one might fail:

1. **All rank and copy information exists only as `GuiObject`s under `PlayerGui`** — the same
   mechanism that made the Phase 4 overlay private.
2. **The Parts that carry those surfaces are anonymous.** Identical size, `Name = "CardSlot"` for
   every card, no attributes, no rank-bearing child, `Transparency = 1`, parented under
   `workspace.CurrentCamera`. So **even if a client-created Part did replicate** (U1 is unverified and
   two people have now searched for a doc statement and found none — do not spend a third search), it
   would reveal "someone has a card here", which is what a count already tells everyone, and no rank.
   This client's hand size is the only thing a replicated carrier could add, and it is derivable from
   public pile counts.
3. **Other seats get no card objects at all** (D-46), unchanged from Phase 4.

**The face vocabulary does not change (D-48).** `Faces`, the 50 identity keys, the
`(rankGlyph, pipShape)` key, the greyscale rule, the machine-gated 4.5:1 luma floor and `CardTheme`
as the single colour and font home all survive untouched. The faces are rendered **onto a surface
instead of into a `Frame`**. The rendered SIZE changes, so M-14 is re-run; the vocabulary does not
change, so M-14 is not re-designed.

**This plan is ADDITIVE to `CardFace`.** The Phase 4 2D card API (`moveToSlot`, `flyTo`, `placeAt`,
`setSolution`) stays until plan 07 deletes it, because `CardHand` still calls it and the tree must
typecheck and stay green at every wave. Adding the tree builder now and deleting the dead API in the
plan that removes its last caller is the sequencing that keeps every intermediate commit shippable.

Output: the face-tree builder, the carrier, and the two headless privacy gates.
</objective>

**The carrier, property by property.** Part: `Name = "CardSlot"` for **every** card, size =
`CARD_STUDS`, `Anchored = true`, `CanCollide = false`, `CanQuery = false`, `CanTouch = false`,
`CastShadow = false`, `Transparency = 1`, **no attributes, no children**, parented under
`workspace.CurrentCamera`. SurfaceGui: parented to **`PlayerGui`**, `Adornee = part`,
`Face = Front`, `SizingMode = PixelsPerStud`, `PixelsPerStud = 40 * CANVAS_SCALE`,
`Active = false`, `ResetOnSpawn = false`, and — **the one route-dependent pair** —
`AlwaysOnTop = (LAYERING_ROUTE == "AlwaysOnTop")` with `ZOffset = slotIndex` set only in that case.
Inside: one `UIScale` of `CANVAS_SCALE` and the unchanged face tree.

`CANVAS_SCALE = 3` keeps texel density at or above one per screen pixel up to `k = 3`, i.e. up to
fullscreen height 1092 — so 1080p is exactly covered and 1440p and 4K are slightly soft. **Accepted**
(Open Question 5); the escalation if M-14 on glass disagrees is `CANVAS_SCALE = 4`, whose only cost is
the M-22 measurement.
