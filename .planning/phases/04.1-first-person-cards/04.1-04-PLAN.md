<objective>
Two jobs, both about **coordinates**, and both about a bug class that passes at the desk and fails on
glass.

**One: the inset recipe becomes a pure function (checker F1, HIGH).** The UI-SPEC's first draft
derived the inset origin by hand — `left + right = fullW - AbsoluteSize.X` plus
`GuiService:GetGuiInset().Y`. That was **under-determined and probably wrong**: one width difference
cannot separate the left inset from the right one, and `GetGuiInset` is the legacy top-bar semantic,
not notch-aware `CoreUISafeInsets`. The headless spec took insets as given, so it could never have
caught the error; only a notched device would have, and it would have shifted **every hit target** by
the height of the top bar.

**`GuiService:GetInsetArea(screenInsets)` settles it, and the documentation's own worked example is
this plan's test fixture.** VERIFIED on 2026-11-10: the method "returns a `Rect` describing the inset
region **relative to the `CoreUISafeInsets` area**", and the documented example is
`GetInsetArea(None) = (-59, -58, 792, 334)` with `GetInsetArea(CoreUISafeInsets) = (0, 0, 733, 313)`.
So `-Min` **is** the origin, `Max - Min` **is** the fullscreen extent, and the remaining two insets
follow: `right = 851 - 59 - 733 = 59`, `bottom = 392 - 58 - 313 = 21`. **That arithmetic is now a pure
function, `Projection.viewportFrom`, driven by the doc's own numbers** — which, note, reproduce the
spec's notched reference almost exactly (L/R 47..59, B 21). The renderer makes two documented calls
and does no arithmetic. **This also moves U5 to VERIFIED.**

**Two: `Layout` gives up the hand and keeps the chrome.** `Layout.solve` keeps the strip, the drain,
both piles, the callouts, the safe rect and the scale. Its `fan`, `slots` and `handZone` members are
superseded by `Projection`. The `TableRegion` is **redefined, not deleted**: it becomes the band from
the safe top to the strip top, so `CardCallout`, `CardHud` and `CardFlourish` keep working against the
member they already use, and the 58% bound becomes the measured-down **47% to the strip top**.
`HandZone` becomes the **hit layer** — same name, same parent role, no plate, now spanning strip top
to safe bottom — so `CardStrip` and `CardPiles` keep their existing arithmetic and this plan does not
spill into three more files. **Every retired `problems` check is listed with its successor; none is
deleted silently.**

Output: the pure inset function, its spec, the retired-and-re-anchored `Layout`, and `layout.spec`
brought to the new contract.
</objective>

```luau
--!strict  -- added to src/shared/Card/Projection.luau (still PURE)
-- Both arguments are plain tables with the four numbers a Roblox Rect carries. The renderer
-- converts two GuiService:GetInsetArea results into these and does NO arithmetic of its own.
export type RectMinMax = { minX: number, minY: number, maxX: number, maxY: number }
Projection.viewportFrom = function(none: RectMinMax, coreUISafe: RectMinMax) -> Viewport
-- origin  = (-none.minX, -none.minY)               -- core-UI origin -> fullscreen origin
-- full    = (none.maxX - none.minX, none.maxY - none.minY)
-- safe    = (coreUISafe.maxX - coreUISafe.minX, coreUISafe.maxY - coreUISafe.minY)
-- insets  = { left = origin.x, top = origin.y,
--             right = full.x - origin.x - safe.x, bottom = full.y - origin.y - safe.y }
-- errors by name on any negative inset or non-positive extent: a nonsense viewport must not
-- silently become a layout.
```

```luau
--!strict  -- src/shared/Card/Layout.luau, changed members
-- RETIRED from Solution: fan, slots, handZone-as-plate
-- REDEFINED: tableRegion = { safe top .. strip top }         (the callout / overlay band)
--            handZone    = { strip top .. safe bottom }      (the HIT LAYER; no plate, not Active)
--            tableRegionFraction -> tableBandFraction = tableRegion.h / viewport.height   (fullscreen H)
-- NEW in DESIGN: TABLE_BAND_MIN_FRACTION = 0.47, MIN_FULL_HEIGHT = 360
-- RETIRED from DESIGN: HANDZONE_H, HIT_W, HIT_LAST_W, HIT_H, FAN_BOTTOM_MARGIN,
--            TABLE_REGION_MIN_FRACTION, TABLE_REGION_HEIGHT_GUARANTEE, TABLE_PROJECTION_MARGIN
-- KEPT in DESIGN (the face tree and the stud conversion both depend on them):
--            CARD_W 72, CARD_H 92, STEP 60, LIFT 16, INDEX_INSET_X 16, INDEX_INSET_Y 4,
--            TOUCH_FLOOR_PHYSICAL 48, scale clamp 0.85..1.5 (2D CHROME ONLY), everything else
Layout.solve = function(viewport: Viewport, handSize: number, d: Design?) -> Solution  -- SIGNATURE UNCHANGED
-- strip bottom = Projection.liftedTopPx(viewport, handSize) - DRAIN-adjacent margin * scale
-- strip is full safe width, STRIP_H high, as before; drain is still its bottom DRAIN_H
```

**The signature does not change**, deliberately: `CardHud`, `CardPiles`, `CardStrip`, `CardCallout`
and `CardFlourish` all call `solve` and none of them should learn a new parameter. `Layout` gets the
projected lifted top by **requiring `Projection` itself**, so a caller cannot pass a stale number —
the failure mode a `handTopPx` parameter would have introduced.

**The scale clamp is now explicitly 2D-chrome-only.** It governs the strip, the piles, the callouts
and the rail. **It does not apply to the hand**, whose size is `k(fullH)` with no clamp, proved by
projection. The header must say this in one line, because a reader who assumes otherwise will try to
"fix" the hand with a clamp and silently break the 48 px proof.
