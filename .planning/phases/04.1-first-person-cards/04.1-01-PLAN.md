<objective>
**WAVE 0. THE SPIKE. NOTHING ELSE IN THIS PHASE MAY START BEFORE THIS PLAN IS DONE.**

Two questions this plan settles, and one it deliberately cannot.

**Settled: what a card physically IS.** `AlwaysOnTop = true` is documented as "always renders on
top of 3D content"; `ZOffset` is documented as layering "in relation to others **on the same
face**". **Neither sentence covers two `AlwaysOnTop` SurfaceGuis on different Parts**, and
`AlwaysOnTop` plausibly bypasses depth testing — which would make the 0.05-stud depth step
meaningless and `ZOffset = slot` the wrong mechanism. **A fan whose layering is wrong is not a
fan**: later cards must sit above earlier ones or the overlap reads as noise and the corner index —
the only part of a covered card a player can see — is drawn by the wrong neighbour.

**Settled: that the answer is cheap to apply.** Routes A and B **share every geometric number**.
The card CFrames, the projected quads, the hit rects and the 48 px proof are identical under both;
only three property assignments on the surface differ. That is the structural fact this plan
installs and gates, and it is what lets the other nine plans proceed before the Studio session
happens. Route C is the only route that would change the geometry contract, and the decision doc
records a finding that makes it the expensive last resort rather than a cheap fallback (see the doc:
vanilla Roblox `GuiObject`s have **no shear or skew**, so a true perspective quad is not drawable as
a rotated rectangle — route C is a BLOCKER-grade rewrite, not a tweak).

**Not settled, and honestly not settleable here: the observation itself.** It needs Studio, and the
owner is asleep. So this plan ships the probe, the decision rule, the provisional route **and** a
machine gate that makes the consequences of the other answer impossible to forget. The empirical
half is **M-18**, blocking for the phase's close.

This plan also writes **every** new MANUAL-CHECKS row for the phase, **first**, before any renderer
code exists — Phase 4's rule from plan 04-02, for the same reason: four of this phase's six success
criteria are device-dependent, and a row written after the code is a row a machine can be tempted to
tick.

Output: the manual-check rows, the decision doc, the Studio probe, the config constants and the
contract gate.
</objective>
