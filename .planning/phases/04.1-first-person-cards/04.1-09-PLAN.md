<objective>
The wiring. Everything this phase built becomes the shipped card phase in one file, and that file
stays what its own first line says it is: **plumbing. Any `if` that decides a game outcome belongs in
`src/shared/Card/`.**

Five changes, and deliberately no sixth:

1. The rail is mounted once, into the table-region band, and the existing `setDepths` path drives it.
2. `relayoutAll` grows the rail, so a rotation or resize moves all five 2D pieces together.
3. **`buildDealGeometry` returns `nil`, which retires the 2D flourish deal — and this is where that
   question gets answered rather than left implicit.** The UI-SPEC says the hand-build **is** the
   deal: plan 07's four cards leave the left-pile anchor staggered 0.1 s and settle at 0.48 s. Running
   the 2D `CardFlourish` deal as well would draw a **second** set of cards flying over the 3D ones — a
   double deal. `CardFlourish` is frozen (Phase 7's CARD-18 seam, and it owns the 1.5 s cut-off) and
   it needs no edit: `Stage.deal` is typed `() -> DealGeometry?` and `dealFlourish` already begins
   `if geometry == nil or #geometry.to == 0 then return end` (`CardFlourish.luau:379-381`, read and
   confirmed). **So returning `nil` retires the 2D deal with zero changes to a frozen file**, keeps
   the driver, the cut-off and the seam, and removes `CardClient`'s last read of the deprecated
   `Layout` shim. The header must say the deal is now the hand-build and that the 2D path is
   deliberately dark, not broken.
4. **The `Layout` shim is deleted here, with its last reader.** Plan 04 kept `Slot`, `fan` and
   `slots` as `Projection`-derived members carrying a `DEPRECATED (04.1): deleted by plan 09` note,
   precisely so every intermediate wave would typecheck (`verify.luau` step 8 typechecks all of
   `src/`). Change 3 removes the last reader, so the three members and their notes go, and
   `layout.spec`'s ledger case flips from "the shim is present and agrees with `Projection`" to
   "`solve` returns no `fan` and no `slots`".
5. The teardown order is left **exactly** as it is, because it is already right: `destroyUi` runs
   inside `Controls.onLocalCompleted`'s first step, and plan 03 put the camera release inside
   `restore`, which is the second. **D-30's order is `Controls.onLocalCompleted`'s order and is not
   re-implemented here** — that was true in Phase 4 and stays true.

**`CardHand.new`'s new signature is NOT here.** Plan 07 changes it and updates its own single call
site in the same wave, because the party that changes a signature fixes its callers; leaving it to
this plan would have left the typecheck red for a whole wave.

**What must keep working, and is therefore the thing to check rather than to rewrite:** the
synchronous non-yielding `onCard` handler (V-12 guarantees handler *start* order only, so a yielding
handler could be overtaken and the client would fold events out of order); the hand coming only from
`Sync` (a public `Drew` for the local seat carries an id with no face, so folding it would draw a
blank card); a hider never getting the overlay; exactly one path from an input to a sent intent, and
it goes through the reducer; the fresh reducer per round; the two ordering contracts (`relayout`
before the `apply` that changes the hand size, and the joker mode before the first apply that can
contain a joker); and contained dispatch, so a renderer error does not kill the only handler the
client has.

Output: the wired client and the wiring gate.
</objective>
