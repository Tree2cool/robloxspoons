<objective>
The wiring. Everything this phase built becomes the shipped card phase in one file, and that file
stays what its own first line says it is: **plumbing. Any `if` that decides a game outcome belongs in
`src/shared/Card/`.**

Four changes, and deliberately no fifth:

1. `CardHand.new` gets its new arguments — the hit layer, the HUD (for the single pixel-to-GUI
   conversion), the solution, and the camera's `handCF` supplier.
2. The rail is mounted once, into the table-region band, and the existing `setDepths` path drives it.
3. `relayoutAll` grows the rail, so a rotation or resize moves all five 2D pieces together.
4. The teardown order is left **exactly** as it is, because it is already right: `destroyUi` runs
   inside `Controls.onLocalCompleted`'s first step, and plan 03 put the camera release inside
   `restore`, which is the second. **D-30's order is `Controls.onLocalCompleted`'s order and is not
   re-implemented here** — that was true in Phase 4 and stays true.

**What must keep working, and is therefore the thing to check rather than to rewrite:** the
synchronous non-yielding `onCard` handler (V-12 guarantees handler *start* order only, so a yielding
handler could be overtaken and the client would fold events out of order); the hand coming only from
`Sync` (a public `Drew` for the local seat carries an id with no face, so folding it would draw a
blank card); a hider never getting the overlay; exactly one path from an input to a sent intent, and
it goes through the reducer; the fresh reducer per round; the two ordering contracts (`relayout`
before the `apply` that changes the hand size, and the joker mode before the first apply that can
contain a joker); and contained dispatch, so a renderer error does not kill the only handler the
client has.

Output: the wired client and the wiring gate.
</objective>
