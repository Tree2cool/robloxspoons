Three platform facts bind this file, all re-checked on 2026-11-10 against `create.roblox.com`:

- **V-18:** `RespectCanCollide`'s documented *behaviour* is confirmed; its **default is stated
  nowhere on the page.** So D-03's reason is not "the default is wrong" but *"the default is

  explicitly.

- **V-21:** collision-group registration is server-`Script`-only and the engine supports 32 groups.
  This phase spends exactly **one**; Phases 6 and 7 will want their own.

**The raycast closure — the exact shape (research Pattern 2):**

```luau
-- ONE reused RaycastParams (the datatype page sanctions reuse: "you can change all of the members
-- ... allowing you to reuse the same object").
local rayParams = RaycastParams.new()
rayParams.RespectCanCollide = true       -- D-03, EXPLICIT. V-18: the default is documented NOWHERE.
rayParams.CollisionGroup = PLAYERS_GROUP -- ignores parts in groups that do not collide with Players
rayParams.IgnoreWater = true

local function lineOfSight(from: HuntTable.At, to: HuntTable.At): boolean
	local a = Vector3.new(from.x, from.y, from.z)
	local b = Vector3.new(to.x, to.y, to.z)
	local delta = b - a
	local length = delta.Magnitude
	if length <= Hunt.LOS_END_TRIM then
		return true                       -- already touching; a zero-length ray is not a question
	end
	-- The direction's MAGNITUDE is the ray length (WorldRoot page), so the direction must be the
	-- full vector to the target, trimmed so the ray stops just short of the spoon's own surface.
	local shortened = delta.Unit * (length - Hunt.LOS_END_TRIM)
	return Workspace:Raycast(a, shortened, rayParams) == nil
end
```

`abortHunt(roundId)`: disconnect the sweep, restore the collision pair to **collidable**, `pcall`
`table_:finish("Aborted")` if it exists (it publishes `HuntEnd` to whoever already heard anything,
or no-ops if `start` never ran), `pcall` `lifecycle:endRound(roundId, "Aborted")` if a roundId was
taken, `table_ = nil`, and `onTelemetry("hunt_begin_failed", {})`.

**Six decisions this plan takes:**

| # | Decision | Why |
|---|---|---|
| 1 | `beginHunt` returns `number?` (the roundId), not a boolean | Plan 05-18 needs the roundId to abort cleanly when `cardService:startRound()` fails after the clock already started. A boolean would force Main to re-derive it from `lifecycle:activeRound()`, which is a second source of truth for the same fact |
| 2 | `beginHunt` is called **before** `cardService:startRound()` | This file owns the round clock now (F1: `beginRound` had no caller at all). If cards started first and the clock failed to start, there would be no 5:00 cap and no end condition — a round that never finishes. Starting the clock first means a later card failure is recoverable through the existing single-fire `endRound` path |
| 3 | `MOVE_SAMPLE_EVERY` decides the movement rate **inside the pure core**, so there is **one** accumulator | Two accumulators double the surface plan 05-17's `sweepProblems` scan has to cover, and the pure core can count ticks with a test watching it. `05-PATTERNS.md` says exactly this |
| 4 | `eyeFromRoot = Placement.EYE_HEIGHT - Placement.REACH_HEIGHT`, computed **here**, once | Research F5: adding the full `EYE_HEIGHT` to a root that already sits ~3 studs above the floor puts the eye ~7 up and sees over every 6.5-stud ledge the Phase 3 validator treats as occluding. Plan 05-01 deliberately did not add a constant restating this difference, so this is the single site. **M-29** measures it |
| 5 | `positionOf` returns a **plain table**, and returns nil for no player, no character, no root **or health 0** | A `Vector3` must not reach a pure core. The health check is Pitfall 9's "a dead seeker is not a seeker"; without it a corpse keeps revealing spoons at the position it fell |
| 6 | The `Rng` is seeded with a **mixed, non-sequential** source, reusing `CardService`'s `freshSeed` shape | `Rng.luau`'s header documents that xorshift32 seeded with a small integer yields a constant first output, and the spoon layout must not be guessable (ASVS V6). **Never a round counter.** If `CardService.freshSeed` is not exported, write the same expression here with a comment naming the warning — and say in the summary which it was, because a duplicated expression is a thing plan 05-17 should scan |
