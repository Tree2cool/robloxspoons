```luau
--!strict
-- src/server/core/HuntRouting.luau   (PURE ZONE)
export type Audience = "owner" | "all"

export type Publisher = {
	toPlayer: (userId: number, kind: string, payload: unknown) -> (),
	toAll: (kind: string, payload: unknown) -> (),
}

export type Effects = {
	fireToPlayer: (userId: number, kind: string, payload: unknown) -> (),
	fireToAll: (kind: string, payload: unknown) -> (),
}

local KINDS = { "HuntStart", "SpoonVisible", "SpoonHidden", "SpoonsRemaining", "ClaimOk", "Spectate", "HuntEnd" }
table.freeze(KINDS)

local AUDIENCE: { [string]: Audience } = {
	HuntStart = "owner",
	SpoonVisible = "owner",
	SpoonHidden = "owner",
	SpoonsRemaining = "all",
	ClaimOk = "owner",
	Spectate = "owner",
	HuntEnd = "all",
}
table.freeze(AUDIENCE)

local PRIVATE_KINDS: { [string]: true } = {
	HuntStart = true,
	SpoonVisible = true,
	SpoonHidden = true,
	ClaimOk = true,
	Spectate = true,
}
table.freeze(PRIVATE_KINDS)

-- Payload shapes, exported as types so a drifting producer is a typecheck failure and not a leak.
export type VisiblePayload = { id: number, x: number, y: number, z: number }
export type HiddenPayload = { id: number }
export type RemainingPayload = { count: number }
export type ClaimOkPayload = { spoonId: number }
export type StartPayload = {}
-- FLAT numbers, and deliberately NOT named x/y/z: the privacy oracle walks payloads by key name, and
-- map bounds are public data that must never be mistaken for a spoon position by a reader of either
-- the code or the oracle's output.
export type SpectatePayload = { minX: number, minY: number, minZ: number, maxX: number, maxY: number, maxZ: number }
export type ScoreRow = { userId: number, bonus: number, find: number, total: number }
export type EndPayload = { reason: string, rows: { ScoreRow }, hiderId: number, hiderScore: number }

local function audienceOf(kind: string): Audience      -- errors on an unknown kind
local function assertPublic(kind: string)              -- errors unless audience is "all" and the kind is not private
local function makePublisher(effects: Effects): Publisher
```

**Three decisions this plan takes:**

| # | Decision | Why |
|---|---|---|
| 1 | `Effects` has **two** closures, not `CardRouting`'s four | `CardRouting` needs `fireToMany` and `seatedUserIds` because its public audience is the *seated* set, which lives in `CardService`. The hunt's public audience is everyone (`FireAllClients`) and its private fan-out is per-user. `SpoonHidden` after a claim goes to exactly the set that had that spoon visible (Pitfall 4) — a handful of users, each by `toPlayer`, which the caller already iterates. A `fireToMany` nobody calls is dead code in the one file whose whole value is being enumerable |
| 2a | **O7: the reveal payload is position only** (`id, x, y, z`) — no surface normal, no orientation | The glint is a billboard/glow, not an oriented object, so a normal would be data nobody renders. Skins arrive in Phase 7 and **must not** be anticipated here (D-18) |
| 2 | `HuntEnd` is audience `"all"` and carries **no positions** | A scoreboard is public. Revealing *unfound* spoon positions at the podium is SCORE-09, Phase 7, using the hider's placement effect — it is not this phase's and the payload type above has no room for it |
| 3 | `Spectate`'s bounds are six flat numbers, not nested `min`/`max` `Vec3`s | The plan-05-15 privacy oracle flattens every number out of every payload and compares triples against spoon positions. Nested `{x,y,z}` tables in a legitimately public payload make that oracle's output harder to read and invite a reviewer to stop trusting it |
