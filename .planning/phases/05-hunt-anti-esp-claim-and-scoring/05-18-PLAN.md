<objective>
The wiring that makes the round a round. This plan closes research finding **F1**, which is the
largest single gap in the phase.

Purpose: `grep` over `src/` found that **`RoundDriver.beginRound` has no caller.** `Main.server.luau`
constructs `RoundDriver.new(function(roundId, reason) print(...) end)` and never starts a round;
`CardService.endRound` has no caller either, only `destroy`. So **today there is no 5:00 cap, no
`AllSpoonsClaimed` end, and the card stub's round never ends.** SCORE-05 and ROADMAP success
criterion 4 need all of it, and nothing in Phase 4 noticed because Phase 4 never needed a round to
finish.

Two orderings in this file are load-bearing and both have precedents:

**`huntService:finish(roundId, reason)` runs BEFORE `cardService:endRound()`.** The hunt's `finish`
builds the scoreboard from live state and publishes it (plan 05-12); `cardService:endRound()`
releases avatars, publishes `RoundEnd` and clears `seated`. Reversing them would publish the card
round's end before the hunt's scoreboard existed, and the hunt would then finalise against a table
whose audience had already been torn down. This is the same lesson as Phase 4's
`RoundEnd`-before-`table.clear(seated)` bug, one level up.

**`huntService:beginHunt()` runs BEFORE `cardService:startRound()`.** `beginHunt` owns the clock
now. If cards started first and the clock failed to arm, there would be no cap and no end condition —
a round that never finishes. Starting the clock first makes a later card failure recoverable through
the existing single-fire `endRound` path.

And the F2 discipline lands here as a single deliberate line: **`onCompleted(seat, playerId, rank)`
forwards only `playerId`.** The card rank is discarded at the call site, with a comment, because
`HuntService.onSeekerCompleted` has no rank parameter to give it to.

Output: the wired `Main.server.luau` and `tests/hunt/main_wiring.spec.luau`.
</objective>
