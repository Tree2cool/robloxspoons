needed a decision rather than an edit. This is research **Open Question O1**, answered: a new file,
reversible by one edit if the owner prefers the eleventh constant.

**Fifteen keys. The lock spec's count message is `a sixteenth constant must be decided, not slipped in`.**

**Four decisions this plan takes, each recorded in the file header:**

| # | Decision | Why |
|---|---|---|
| 1 | `MOVE_SAMPLE_EVERY = 1` — the movement sampler runs on **every** 5 Hz sweep tick | D-07 asks for "about 4 Hz". 5 Hz is strictly more samples than 4, which is the conservative direction for catching a teleport. A genuine 4 Hz rate from a 5 Hz accumulator is not an integer ratio, so it would cost a second accumulator — and `05-PATTERNS.md` is explicit that two accumulators double the source-scan surface the adapter gate has to cover. The constant stays so Phase 8 can decimate to every 2nd tick if the profile asks |
| 2 | `HIDER_DENOM_SECONDS` is its own constant, equal to `Round.ROUND_CAP_SECONDS` today | Open Question 7 locked a **fixed** 300 s denominator. If the two shared one constant, retuning the round cap would silently move the hider's denominator and SCORE-04 would quietly stop meaning what the owner confirmed. The lock spec asserts they are equal **and** that they are two independent keys |
| 3 | The scoring constants live here, not in a new `Config/Scoring.luau` | A second file costs a second lock spec, and nothing but the hunt consumes these. Also: `Scoring` is a `guardedNamePrefixes` entry (`scripts/ci/zones.luau:62`), so a shared file called `Scoring.luau` would become a FOUND-05 root whose R3 `os.` needle scans its own text — correct but pointless for a table of numbers, and confusing beside `src/server/core/Scoring.luau` |
| 4 | There is **no** `EYE_FROM_ROOT` constant | Research F5 wants the eye at `EYE_HEIGHT - REACH_HEIGHT` above the root. Both are locked `Placement` values. A third constant restating their difference is exactly the "second copy is how a locked value drifts" failure `Config/Card.luau` warns about. The adapter (plan 05-14) computes the difference and passes it in as a value; the lock spec asserts the difference is positive |

**Things deliberately NOT in this file,** listed in the header: `PICKUP_RANGE`, `PICKUP_MARGIN`,
`EYE_HEIGHT`, `REACH_HEIGHT` (they stay in `Placement.luau` and are read from there),
`ROUND_CAP_SECONDS` and `DECISECONDS_PER_SECOND` (they stay in `Round.luau`), and any glint
*appearance* value (D-18: the glint is fixed and non-purchasable, and this phase builds no seam for a
variant — so a `GLINT_*` entry that is a table rather than a number is a review failure, and the lock
spec asserts it).
