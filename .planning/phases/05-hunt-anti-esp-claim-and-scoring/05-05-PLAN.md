<objective>
The pure scoring module and its ledger: the only place in the game that turns a clock reading and a
finishing place into points.

Purpose: three things make this worth its own plan.

**D-13 put it here on purpose, and the name is load-bearing.** D-13: *"Scoring is a PURE module at
`src/server/core/Scoring.luau` — no Roblox API, so the worked examples run headless in CI."* And it is a
named FOUND-05 root. `scripts/ci/zones.luau:62` lists `guardedNamePrefixes = { "Scoring",
"CardTable", "SpoonPlacement" }`. The filename is load-bearing: the moment `Scoring.luau` exists,
`check-guards` enforces that no transitive require path from it names `cosmetic`, `shop`, `catalog`,
`loadout`, `economy`, `monetiz`, `gamepass`, `purchase` or `skin`. That is what makes CLAUDE.md
rule 4 — no purchase may affect a competitive outcome — true rather than promised.

**The decisecond makes one bug class vanish.** Find points are 10 per second and the clock is
integer deciseconds, so **find points equal remaining deciseconds exactly** (10 points/s ÷ 10
deci/s = 1 point per deci). There is no rounding rule for find points, and plan 05-01's config lock
asserts the 1:1 ratio so nobody can introduce one.

**The hider score is the one place a rounding rule does exist,** and the ROADMAP gives no hider
vector except the ceiling. This plan derives vectors, labels them derived, and — critically —
includes the one vector that can actually tell a half-up rule from a truncating one. The obvious
boundary vectors cannot: at all-unfound both give 4000 and at all-found-at-zero both give 0. A
rounding gate built only on the boundaries **cannot fire**, which is this repo's recurring failure
wearing a new hat.

Output: `src/server/core/Scoring.luau` and `tests/hunt/scoring.spec.luau`.
</objective>

```luau
-- src/server/core/Scoring.luau   (PURE ZONE, FOUND-05 guarded root by name)
export type Config = {
	BONUS_FIRST: number,        -- 1000
	BONUS_STEP: number,         -- 100
	CAP_DECI: number,           -- 3000 = Round.ROUND_CAP_SECONDS * DECISECONDS_PER_SECOND
	HIDER_DENOM_DECI: number,   -- 3000 = Hunt.HIDER_DENOM_SECONDS * DECISECONDS_PER_SECOND.
	                            --        A SEPARATE constant from CAP_DECI; equal today by decision,
	                            --        not by identity (Open Question 7 locked a FIXED 300 s).
	HIDER_MAX: number,          -- 4000
	POINTS_PER_DECI: number,    -- 1
}

-- SCORE-01. Non-increasing, floored at zero: place 11 pays 0, and the roster caps at 10 so place 10
-- pays 100.
function Scoring.bonus(cfg: Config, place: number): number

-- SCORE-02. The deadline is EXCLUSIVE (RoundLifecycle): arrival == deadline pays nothing.
function Scoring.findPoints(cfg: Config, deadlineDeci: number, arrivalDeci: number): number

-- SCORE-04. `survivedDeci` is one entry per spoon the hider placed: the elapsed deciseconds before
-- it was found, or HIDER_DENOM_DECI for a spoon never found.
-- ROUNDING RULE, stated here because a comment cannot fail but a header can be read:
--   score = round_half_up(HIDER_MAX * sum / (HIDER_DENOM_DECI * n))
--         = floor((2 * HIDER_MAX * sum + HIDER_DENOM_DECI * n) / (2 * HIDER_DENOM_DECI * n))
-- All integer arithmetic. Float division would drift and break exact-equality tests.
function Scoring.hiderScore(cfg: Config, survivedDeci: { number }): number

export type Row =
	{ kind: "Bonus", userId: number, place: number }
	| { kind: "Find", userId: number, spoonId: number, arrivalDeci: number }

export type Entry = { userId: number, bonus: number, find: number, total: number }
export type Scoreboard = { rows: { Entry }, hiderId: number, hiderScore: number }

export type Ledger = {
	recordBonus: (self: Ledger, userId: number, place: number) -> (),
	recordFind: (self: Ledger, userId: number, spoonId: number, arrivalDeci: number) -> (),
	rows: (self: Ledger) -> { Row },          -- a COPY, append-only
	-- `spoons` is one entry per placed spoon: its arrival deci, or nil for never found.
	finalize: (
		self: Ledger,
		cfg: Config,
		deadlineDeci: number,
		spoons: { number? },
		hiderId: number
	) -> Scoreboard,
}
function Scoring.newLedger(): Ledger
```

**Four decisions this plan takes:**

| # | Decision | Why |
|---|---|---|
| 1 | `finalize` derives each spoon's **survived** time from the same two numbers find points use: `survived = CAP_DECI - findPoints_remaining = CAP_DECI - max(0, deadlineDeci - arrivalDeci)`, and `HIDER_DENOM_DECI` for an unfound spoon | SCORE-04 says the hider is scored *"on the same timeline as find points"*. Deriving survival from `deadlineDeci - arrivalDeci` rather than from a separately tracked start time makes the two timelines the same expression, so they cannot disagree. A second start-time field is a second clock in miniature |
| 2 | `Scoreboard.rows` is **sorted by `userId` ascending** | Luau table iteration order is unspecified, so an unsorted scoreboard makes every `deepEqual` in every downstream spec order-dependent and intermittently red. Determinism here is cheaper than flakiness everywhere |
| 3 | A seeker with a `Bonus` row and no `Find` row appears in `rows` with `find = 0` | That is SCORE-03 made structural: the bonus is kept and the find is zero, and a seeker who simply vanished from the scoreboard would be indistinguishable from one scored at zero |
| 4 | `hiderScore({})` — no spoons placed — returns **0**, not an error | `n = 0` would divide by zero. A 3-player round places `3 - 2 = 1` spoon so the real game never hits it, but plan 05-09 calls this during `finish` after a round where every spoon could in principle have been removed. A loud error during round-end finalisation would lose the whole scoreboard; 0 with a recorded reason does not |

**The rounding discriminator, spelled out because getting this wrong is the likely failure:**

| Vector | Half-up (correct) | Truncating (the mutant) | Discriminates? |
|---|---|---|---|
| `n = 2`, all unfound → `survived = {3000, 3000}` | 4000 | 4000 | **no** |
| `n = 2`, all found at deci 0 → `{0, 0}` | 0 | 0 | **no** |
| `n = 2`, `{3000, 1500}` → sum 4500 | 3000 | 3000 | **no** |
| **`n = 2`, `{3000, 1}` → sum 3001** | **2001** | **2000** | **YES** |

`4000 * 3001 / (3000 * 2) = 2000.666…`, whose fractional part exceeds a half. Integer form:
`floor((8000 * 3001 + 6000) / 12000) = floor(2001.1666…) = 2001`. **The spec must carry this vector
and say in a comment that the three obvious boundary vectors cannot tell the two rules apart.**
