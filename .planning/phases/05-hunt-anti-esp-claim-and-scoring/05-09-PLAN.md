<objective>
The composing core: the one object that owns the hunter set, the place counter, the spectators, the
registry, the visibility state, the plausibility sampler and the ledger — with every effect injected.

Purpose: this is `CardTable`'s sibling and it inherits `CardTable`'s discipline, but one thing in it
is new and is the single most dangerous bug available in this phase.

**`Completed.rank` is the CARD RANK, not the finishing place.**
`src/server/engine/Types.luau:24` reads `export type Rank = number -- 1..config.ranks for naturals;
JOKER_RANK (0) for a joker`, and `CardTable.Deps.onCompleted(seat, playerId, rank)` passes
`event.rank`. SCORE-01 is *"1000 for the first to four of a kind, −100 per place after"* — that is
**finishing order**. Scoring off `rank` would produce plausible-looking, wrong bonuses: a player
completing four 7s would be paid as if they finished 7th. The numbers would look like scores, the
suite would be green, and the game would be wrong.

The structural fix, taken here: **`onSeekerCompleted` takes only a `playerId`.** There is no `rank`
parameter, so using the card rank as a place is not merely discouraged — it is inexpressible. Plan
05-18's `Main.server.luau` discards the rank at the call site, on purpose, with a comment.

Plan 05-12 adds `claim` and `finish` into a marked insertion point in this same file, so this plan
leaves one.

Output: `src/server/core/HuntTable.luau` and `tests/hunt/hunt_table.spec.luau`.
</objective>

**`start(spots, playerCount, hiderId)`:**
1. Error if already live.
2. `count = math.max(0, playerCount - cfg.spoonsFewerThanPlayers)`; `registry:autoFill(spots, count)`.
   A `count` above the supply is `SpoonRegistry`'s loud error, and plan 05-14 turns that throw into a
   refusal telemetry event.
3. `live = true`; `placeCounter = 0`; `hiderId` stored; `spectators[hiderId] = true` (O4).
4. Publish `Spectate` to the hider with `cfg.bounds`, then `SpoonsRemaining { count }` to all.
5. `onTelemetry("hunt_started", { spoons = count, players = playerCount, hider = hiderId })`.

**`onSeekerCompleted(playerId)`:**
```
if not live then                 onTelemetry("hunt_completed_ignored_not_live", { userId = playerId }) ; return end
if hunters[playerId] ~= nil      then return end         -- idempotent; a duplicate completion is not a second place
if spectators[playerId]          then return end         -- already finished, or the hider
placeCounter += 1
local place = placeCounter                                -- NOT a card rank (F2)
hunters[playerId] = { spoonId = nil }
ledger:recordBonus(playerId, place)
publisher.toPlayer(playerId, "HuntStart", {})
onTelemetry("hunt_seeker_joined", { userId = playerId, place = place, remaining = registry:remaining() })
```

**`tick()`:**
```
if not live then return end
if not deps.lifecycleOpen() then return end   -- Pitfall 5: isOpen may END the round re-entrantly,
                                              -- and finish() will have set live = false by the time
                                              -- this returns. Return, do not continue with stale
                                              -- locals.
local hunterIds = sorted ids of hunters where entry.spoonId == nil
local shown, hidden = Visibility.step(vis, hunterIds, registry:unclaimed(), eyeOf, deps.lineOfSight, cfg.visibility)
-- PUBLISH AFTER THE STEP (the step already mutated its own state; rule 6's shape)
for _, t in shown  do publisher.toPlayer(t.userId, "SpoonVisible", { id = t.spoonId, x = ..., y = ..., z = ... }) end
for _, t in hidden do publisher.toPlayer(t.userId, "SpoonHidden",  { id = t.spoonId }) end
tickCount += 1
if tickCount % cfg.moveSampleEvery == 0 then
    for _, userId in hunterIds do plaus:sample(userId, deps.positionOf(userId), deps.walkSpeedOf(userId), deps.nowDeci()) end
end
```
`eyeOf = function(userId) return Visibility.eyeOf(deps.positionOf(userId), cfg.visibility) end`.

**`removePlayer(userId)`** — the one generic removal (rule 8):
```
hunters[userId] = nil
spectators[userId] = nil
Visibility.forget(vis, userId)
plaus:forget(userId)
onTelemetry("hunt_player_removed", { userId = userId, remaining = registry:remaining() })
```

**Four decisions this plan takes:**

| # | Decision | Why |
|---|---|---|
| 1 | `onSeekerCompleted` has **no** `rank` parameter | Research F2. Making the wrong thing inexpressible beats commenting that it is wrong. Plan 05-18 discards the rank at the call site |
| 2 | `tick` asks `deps.lifecycleOpen()` **before** stepping visibility | Pitfall 5: `isOpen` routes an expired round to a `Timeout` end, which runs `finish` synchronously and sets `live = false`. A sweep that continued after that would publish reveals into a dead round |
| 3 | The hider is a **spectator** from `start` (O4), and `hunters` never contains them | A spectator receives no reveals by construction, because `tick` builds `hunterIds` from `hunters`. The hider wandering the map during the Phase 5 stub is harmless and is Phase 6's to change |
| 4 | A hunter with `spoonId ~= nil` (they already claimed) is excluded from `hunterIds` | They are finished. Plan 05-12 also moves them to `spectators` and calls `Visibility.forget`, but excluding them here means the sweep is correct even in the window before that runs |
