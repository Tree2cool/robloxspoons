<objective>
The anti-ESP gate: the one spec that answers ROADMAP criterion 1's machine-checkable half.

Purpose: `tests/card/privacy.spec.luau` opens with the sentence this file inherits — *"every
assertion reads what was actually called, never what the router claims."* That distinction is the
whole design. A gate that asked `HuntRouting.AUDIENCE` whether `SpoonVisible` is private would pass
forever while the shipped code broadcast it; this one collects every publisher call the **real**
`HuntTable` made and interrogates the payloads.

It must also be **non-vacuous**, and that is the harder half. A privacy oracle that finds nothing is
indistinguishable from an oracle that looked at nothing. So every helper returns a count the test
asserts: how many nodes it visited, how many candidate position triples it saw, how many reveals the
entitled path actually produced. `tests/card/privacy.spec.luau`'s `publicWalkProblems` returns
`(problems, nodesVisited, publicCalls)` for exactly this reason — mirror it.

And it must be **proven able to fire**. `tests/harness/HuntRecording.luau`'s `leak` switch is silent
by design, *"because one that announced its own defect would let a gate pass by reading the
announcement instead of the routing."* Five injected leaks, each driven through the same checking
helper as the clean path, plus a no-defect identity twin that must read green so no mutant can be red
for harness reasons.

**The honest split, stated in the spec's own header:** HUNT-01 is machine-proved here for the pure
core, machine-proved in plan 05-17 for the adapter's source text, and **human-proved by M-24** for
the live client DataModel. Say all three, the way `service_wiring.spec` says what it does not prove.

Output: `tests/hunt/privacy.spec.luau`.

**The oracle, stated precisely before it is written:**

> For every recorded publisher call, flatten every number out of the payload recursively. For every
> **unclaimed** spoon and every user, assert that no ordered triple `(x, y, z)` equal to that spoon's
> position appears in a message that user could receive — a `toPlayer` addressed to them, or **any**
> `toAll` — unless that user was **entitled** at the tick the message was sent.
>
> Entitlement is recomputed **independently of `Visibility`'s state**: within `GLINT_RANGE` of the
> spoon from that user's eye at that tick, with the fixture's own line-of-sight flag clear. The
> oracle must not ask `Visibility.sees`, because that is the thing under test.

Returns `(problems, nodesVisited, candidateTriples)`.

**`BANNED_PUBLIC`, per public kind** (research item 2):

| Kind | Audience | Banned keys anywhere in the payload |
|---|---|---|
| `SpoonsRemaining` | all | `x`, `y`, `z`, `position`, `spoons`, `list`, `id`, `spoonId` |
| `HuntEnd` | all | `x`, `y`, `z`, `position`, `spoons`, `list`, `spoonId` |

`HuntEnd` keeps `userId`, `bonus`, `find`, `total`, `hiderId`, `hiderScore` and `reason`. Note why
`id`/`spoonId` is banned from `SpoonsRemaining` but not from the private kinds: a broadcast naming a
spoon id tells everyone a spoon exists and was taken, which is one inference step from "somebody was
standing near it".

**The five mutations** (research item 5), each injected through `wrap` or `leak` and driven through
the **same** checking helper as the clean path:

| # | Mutation | Must fire |
|---|---|---|
| 1 | `leak = true` — every `toPlayer` recorded as a `toAll` | the oracle: positions now reach everyone |
| 2 | a `wrap` whose `toAll("SpoonsRemaining", ...)` appends the full spoon list to the payload | the shape gate |
| 3 | a `wrap` that re-sends every currently-visible spoon on **every** tick | the resend gate |
| 4 | a `wrap` that delivers each `SpoonVisible` to the spectator as well | the audience gate |
| 5 | a `wrap` that delivers each `SpoonVisible` to the **wrong hunter** — a swap, not a broadcast | the oracle, **and not the `leak` switch**: this is the one the `toAll`-shaped mutations cannot catch, and it is the hunt twin of `card/privacy.spec`'s mutation 5 (a `Notice` to the wrong player) |

Plus a **no-defect twin**: a `wrap` that returns the base publisher unchanged, asserted green through
every helper, so no mutant can be red because the harness is.

**Three decisions this plan takes:**

| # | Decision | Why |
|---|---|---|
| 1 | The oracle recomputes entitlement from the fixture's own geometry, **not** from `Visibility.sees` | Asking the module under test whether its own output was allowed is circular. Recomputing costs a few lines and makes the oracle an independent witness |
| 2 | The oracle checks **unclaimed** spoons only | A claimed spoon's position is already known to its claimer and the ROADMAP's requirement is about *hidden* spoons. Checking claimed ones would produce false positives on the legitimate `ClaimOk` path and invite someone to loosen the oracle |
| 3 | Position matching is **exact equality on the ordered triple**, not a distance tolerance | The fixture sets spoon positions, so the values that cross the wire are the same doubles. A tolerance would make the oracle's failures fuzzy and its passes arguable. M-24's live audit uses 0.5 studs because it compares against a *rendered* position; this one does not have to |
