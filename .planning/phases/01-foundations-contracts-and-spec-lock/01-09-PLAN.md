**Platform facts that shape this design (from current Roblox docs):**
- RemoteEvents are reliable and ordered per connection per direction, **including across different
  RemoteEvent instances**, and the ~500/s client throttle is shared across all remotes of the same
  type. So splitting per intent buys nothing; one envelope remote is both simpler and the
  structural proof of "single gateway".
- Ordering is guaranteed for handler **start**, not completion. Never rely on completion order.
- A client firing above the throttle has its excess **delayed, not dropped**, so a flood becomes a
  server-side backlog. The server bucket must therefore **drop and count**, never queue.
- Messages arriving with no handler connected are queued in a bounded queue and then dropped with
  an error, which is why the handler is connected **before** the remote is parented into
  `ReplicatedStorage`.

```lua
--!strict
-- The single typed gateway (FOUND-04). PURE ZONE: no Roblox API, no yields (CLAUDE.md rule 6).
-- The server derives the actor from the RemoteEvent's player argument; the client never names a
-- seat, a target or a hand index (CLAUDE.md rule 7), so `userId` arrives from the adapter and is
-- never read out of the payload.
export type Code = "Ok" | "UnknownIntent" | "RateLimited" | "WrongPhase" | "Malformed" | "HandlerError"

-- D-20 vocabulary, duplicated here DELIBERATELY. `Manifest` lives in `src/shared/Net` and this
-- file lives in `src/server/core`: a relative require between them is a cross-mount require and
-- guard rule R6 fails it. The duplication is made safe by a drift test (see the spec below) that
-- asserts `Gateway.PHASES` deep-equals `Manifest.PHASES`. Do not replace the type with `string`:
-- that is what let a stale phase name through in the first place.
export type RoundPhase = "Lobby" | "Hide" | "Round" | "Podium"

export type Intent = { phases: { RoundPhase }, validate: (value: unknown) -> (boolean, unknown) }

export type Deps = {
	manifest: { intents: { [string]: Intent }, isKnown: (name: unknown) -> boolean },
	bucket: { take: (self: any, userId: number, intent: string, spec: any) -> boolean, forget: (self: any, userId: number) -> () },
	rateFor: (intent: string) -> any,
	getPhase: () -> RoundPhase,
	dispatch: (userId: number, intent: string, payload: unknown) -> (),
	onReject: (userId: number, intent: unknown, code: Code) -> (),
	onError: (userId: number, intent: string, err: unknown) -> (),
}
```

Export the runtime constant too, so the drift test has something to compare:

```lua
Gateway.PHASES = { "Lobby", "Hide", "Round", "Podium" } :: { RoundPhase }
```

`handle(userId: number, intentName: unknown, payload: unknown): (boolean, Code)` runs exactly this
order, cheapest first, and nothing may be reordered:

1. **Known intent?** `manifest.isKnown(intentName)` (which itself checks type and length before
   any lookup). Reject `UnknownIntent` without touching the bucket, so garbage names cannot make
   the server allocate per-name or per-player state.
2. **Token bucket** for `(userId, intentName)` using `rateFor(intentName)`. Reject `RateLimited`.
   Charging **before** validation bounds the CPU an attacker buys with malformed payloads.
3. **Phase gate.** `getPhase()` must appear in the intent's `phases` list. Reject `WrongPhase`.
4. **Payload validation.** `intent.validate(payload)`. Reject `Malformed`.
5. **Dispatch** the validated payload inside `xpcall`. On error route to `onError` and return
   `(false, "HandlerError")`; never let a throwing handler propagate out of `handle` or kill the
   caller's connection.

Every rejection calls `onReject(userId, intentName, code)` exactly once and returns
`(false, code)`. Acceptance returns `(true, "Ok")`.

Also expose `forget(userId)` which delegates to the bucket, so the adapter has one call to make on
`PlayerRemoving`.

Do not read `os`, `tick` or `task`: the clock reaches the gateway only through the injected bucket.
Do not add logging — pure zones have no `warn`; report through `onReject`/`onError`.
