Required implementation details:

- `isFinite` is exactly
  `type(v) == "number" and v == v and v ~= math.huge and v ~= -math.huge`.
  The `v == v` clause is the NaN test: NaN fails every comparison, so a range check alone lets it
  through. This is threat T-1-01.

- `maxDepth = 4` and `maxEntries = 32` are parameters with those defaults, so one message cannot
  buy unbounded server CPU.
- `ForbiddenType` is returned for any `type(v)` outside

  positive type list is also how "no Instances ever" is expressed without naming Roblox.

`src/server/core/Bucket.luau`, `--!strict`, pure zone, injected clock only:

```lua
--!strict
-- Token bucket for the gateway. PURE ZONE: no Roblox API, no yields (CLAUDE.md rule 6).
-- Drops, never queues: a client firing above the Roblox throttle has its excess DELAYED by the
-- platform, not dropped, so a flood becomes a server-side backlog unless the server drops it
-- (research Pitfall 9).
export type Spec = { burst: number, refillPerSecond: number }
export type Store = {
	take: (self: Store, userId: number, intent: string, spec: Spec) -> boolean,
	forget: (self: Store, userId: number) -> (),
	rejections: (self: Store) -> number,
	count: (self: Store) -> number,
}
export type Deps = { clock: { now: () -> number } }
```

Implementation requirements:
- `new(deps)` keeps a two-level table `state[userId][intent] = { tokens, last }`.
- Refill step, exactly as researched:
  `tokens = math.min(spec.burst, tokens + (now - last) * spec.refillPerSecond)`, then `last = now`,
  then grant if `tokens >= 1` and decrement by 1.
- A new `(userId, intent)` pair starts with `tokens = spec.burst`.
- If `now` is not finite, or is less than `last` (a clock that went backwards), do **not** grant:
  treat it as a rejection and leave `last` unchanged. An unchecked clock is a free-token exploit.
- `forget(userId)` sets `state[userId] = nil`. The gateway adapter calls it on `PlayerRemoving`
  so disconnected players do not leak state.
- `rejections()` returns a monotonically increasing count, and `count()` returns the number of
  tracked users, so plan 01-09 can assert the gateway drops rather than buffers.
- No yields anywhere. No `os`, no `task`, no `tick` — the clock is injected.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client payload values to server logic | Every number, string and table field crossing this line is attacker-controlled |
| Client message rate to server CPU and memory | Message volume is attacker-controlled; the platform delays excess rather than dropping it |
| Intent name to per-name server state | An unknown name must not cause an allocation |

## STRIDE Threat Register

**Severity** is `high` / `medium` / `low` and is a required column so "block on high" can be
evaluated mechanically rather than by reading prose. A `high` row whose disposition is `accept`
blocks the phase and must be escalated, not filed.

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
