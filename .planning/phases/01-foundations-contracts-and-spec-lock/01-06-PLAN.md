```lua
--!strict
-- Round FSM (SCORE-06). PURE ZONE: no Roblox API, no yields (CLAUDE.md rules 2, 6).
-- The server is the only clock and all times are integer deciseconds (CLAUDE.md rule 5).
export type Reason = "AllSpoonsClaimed" | "Timeout" | "Aborted"
export type Scheduler = {
	nowDeci: () -> number,
	delay: (seconds: number, fn: () -> ()) -> (() -> ()),
}
export type Deps = {
	scheduler: Scheduler,
	onEnded: (roundId: number, reason: Reason) -> (),
}
export type Lifecycle = {
	begin: (self: Lifecycle, durationSeconds: number) -> number,
	isOpen: (self: Lifecycle, roundId: number) -> boolean,
	endRound: (self: Lifecycle, roundId: number, reason: Reason) -> boolean,
	deadlineDeci: (self: Lifecycle, roundId: number) -> number?,
	activeRound: (self: Lifecycle) -> number?,
	endCount: (self: Lifecycle) -> number,
}
```

Implementation requirements, each of which maps to a behaviour above:

1. `begin(durationSeconds)` increments a monotonic `nextRoundId`, computes
   `endsAtDeci = scheduler.nowDeci() + math.floor(durationSeconds * 10)` as an **integer**,
   registers a backstop `scheduler.delay(durationSeconds, fn)` whose closure **captures the round
   id**, stores the returned cancel closure, and returns the id. Reject a non-finite,
   non-positive or non-numeric duration by erroring — a round with no deadline is worse than a
   crash.
2. **Lazy deadline check.** `isOpen(roundId)` returns false when the id is not active or the round
   has ended; when `nowDeci() >= endsAtDeci` it calls `endRound(roundId, "Timeout")` and returns
   false. `>=` is the exclusive-deadline rule.
3. `endRound(roundId, reason)` returns `false` when `roundId` is not the active round or the round
   has already ended. Otherwise it sets the ended flag **first**, cancels the backstop, and only
   then invokes `onEnded(roundId, reason)` exactly once. No yields between the mutation and the
   publish.
4. The backstop closure compares its captured id against the active id and no-ops on mismatch.
   This guard must work **even if cancel does nothing**, which is why the spec drives it with
   `FakeScheduler.new({ cancelIsNoop = true })`.
5. `endCount()` exposes the number of `onEnded` invocations so tests assert "exactly once" rather
   than "it seemed to work".
6. Never reference `os`, `task`, `tick`, `game` or `warn`: the allow-list lint denies them and the
   scheduler is injected.

Write `tests/core/round.spec.luau` first and watch each case fail. Include the research scenario

100-call idempotence case.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Scheduled callback to live round state | A callback registered by an earlier round executes against whatever state exists when it fires |
| Client-reported time to server logic | A client countdown value must never influence a server decision |
| Handler mutation to event publication | A yield between mutating state and publishing lets two handlers interleave |

## STRIDE Threat Register

**Severity** is `high` / `medium` / `low` and is a required column so "block on high" can be
evaluated mechanically rather than by reading prose. A `high` row whose disposition is `accept`
blocks the phase and must be escalated, not filed.

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-1-04 | Tampering (logic integrity) | high | round backstop callbacks | mitigate | Every backstop closure captures its round id and no-ops on mismatch; proven with `FakeScheduler.new({ cancelIsNoop = true })` so the token guard is demonstrated without relying on `task.cancel` (Task 1) |
| T-1-29 | Tampering | high | double round end / double scoring | mitigate | `endRound` is idempotent: ended flag set before `onEnded`, returns false on a non-active or already-ended round; asserted by a 100-call case and an `endCount` of exactly 1 (Task 1) |
| T-1-30 | Tampering | medium | deadline boundary ambiguity | mitigate | Deadline is exclusive (`nowDeci() >= endsAtDeci` closes the round); a claim exactly on the boundary is rejected; both tie arrival orders asserted (Task 1) |
| T-1-31 | Spoofing | high | client-supplied timing | mitigate | The core takes `nowDeci` only from the injected scheduler, bound to `os.clock()` server-side; `GetServerTimeNow()` is used solely to publish a deadline outward and never fed back in (Task 2) |
| T-1-32 | Tampering | high | interleaved handlers via a mid-mutation yield | mitigate | No yields in the core; the ended flag is set before the publish; the adapter's `task.delay` lives outside the mutation (CLAUDE.md rule 6, Tasks 1 and 2) |
