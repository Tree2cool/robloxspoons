**`scripts/ci/check-guards.luau`** — `--!strict`, run as
`lune run scripts/ci/check-guards.luau [root]` (default root `.`), or
`lune run scripts/ci/check-guards.luau --print-zones` which prints the pure zones space-separated
and exits 0 (CI and `scripts/verify.luau` use that so the Selene invocation and the guard share
one list).

Header comment must state the threat model verbatim: *"This guard defends against accident and
agent drift, not against an adversary with metatable tricks. It is sound inside guarded zones
because it forbids every construct it cannot statically resolve."*

Implementation requirements:

1. **File walk.** Recurse `root/<scanDir>` with `fs.readDir`/`fs.isDir`, collecting `*.luau`.
   Skip any path whose segments intersect `ignoreSegments` **unless** the root argument itself
   points inside such a directory (that is how the fixture suite scans a fixture tree).
2. **Comment stripping.** Before scanning a source, strip `--` line comments and
   `--[[ ]]` / `--[=[ ]=]` / `--[==[ ]==]` block comments (handle any number of `=`). Do **not**
   strip string literals: leaving them in can only cause a loud false positive, which is safe.
   Keep the *unstripped* text too — suppression-comment detection needs it.
3. **Literal require extraction.** On the stripped source, match
   `require%s*%(%s*"([^"]+)"%s*%)` and `require%s*%(%s*'([^']+)'%s*%)`. Record line numbers.
4. **Non-resolvable-construct ban (inside pure zones and guarded roots).** Fail on:
   `require` not immediately followed by a string literal (e.g. `require(script.Parent.X)`,
   `require(someVar)`, `require(table[key])`), `getfenv`, `setfenv`, `loadstring`,
   `rawget(_G`, `_G[`. Rule id `R3`.
5. **Filesystem resolution.** From `a/b/C.luau`: `./X` → `a/b/X.luau`, else `a/b/X.lua`, else
   `a/b/X/init.luau`; `../X` → one directory up; `@self/X` → legal only from an `init.luau`;
   anything else starting with `@` (e.g. `@game/...`, `@lune/...`) is not resolved to disk but is
   kept as a raw target string. A `./` or `../` require that resolves to no file is rule `R6`
   failure ("unresolvable require").
6. **DataModel twin resolution (rule R6).** Using the mount map (read
   `root/default.project.json` when present, else `zones.mounts`), resolve the same require by
   Roblox rules: `./` starts at the requiring module's parent, `../` goes one parent up, and the
   walk may not escape the mount root. If the filesystem resolution succeeds but the DataModel
   walk escapes the mount or lands on a different file, fail with
   `R6 cross-mount require: <file>:<line> "<target>" resolves on disk but not in the DataModel`.
   This is the static twin of the built-place check in plan 01-10 and encodes research Pitfall 1.
7. **FOUND-05 closure (rule R2).** Roots = every file under `root/src` whose basename starts with
   a `guardedNamePrefixes` entry, plus every file inside a `pureZones` directory. Walk requires
   transitively (memoised, cycle-safe). For each visited target — resolved path **or** raw
   `@game/...` string — lowercase it and fail if any path segment contains a `forbiddenSegments`
   entry. The message must name the full chain with ` -> ` separators and basenames without
   extension, e.g. `R2 forbidden import: CardTable -> Util -> ShopCatalog`.
8. **Strict header (rule R1).** Every collected `.luau` must have `--!strict` as its **first
   line** (exact, no leading whitespace). `--!nocheck`, `--!nonstrict` and a missing header are
   all failures. This is FOUND-02's per-file half.
9. **Suppression ban (rule R3b).** Inside pure zones, fail on any of
   `selene: allow`, `--# selene`, `--!nocheck`, `--!nonstrict`, `-- luau-lsp:`,
   `--!native` — detected on the *unstripped* text.
10. **Net hygiene (rule R4).** For each `netOwners` identifier, fail if it appears in any file
    other than its owner path (compare paths relative to root). This makes "single typed gateway"
    structural rather than conventional (FOUND-04, CLAUDE.md rule 7).
11. **Secret names (rule R5).** Fail if any `secretNames` literal appears under `src/client` or
    `src/shared` (CLAUDE.md rule 3 — a client must not even know the vocabulary of hidden data).
12. **Output and exit.** Print one line per violation as
    `<RULE_ID> <relative/path>:<line> <message>`, then
    `check-guards: N violation(s)` and `process.exit(1)`. On success print
    `check-guards: ok (<fileCount> files, <requireCount> requires, <rootCount> guarded roots)` and
    exit 0. **Never exit 0 with violations**, and never swallow an internal error — wrap the whole
    body so an unexpected error also exits non-zero.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gameplay modules → cosmetics/shop modules | The no-pay-to-win promise is an import-graph property; crossing it is invisible at runtime |
| Pure zone → Roblox API surface | The engine's testability and purity depend on there being no path across this line |
| Client/shared code → hidden-data vocabulary | A client that knows the tag names of hidden data is one step from reading them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-19 | Tampering (integrity of the no-pay-to-win guarantee) | `Scoring`, `CardTable`, `SpoonPlacement` import graph | mitigate | R2 transitive closure over literal requires with a case-insensitive forbidden-segment list; proven failing by `import-direct` and `import-transitive` fixtures run through the real CLI (Task 2) |
| T-1-20 | Tampering (guard evasion) | indirection inside guarded zones | mitigate | R3 bans non-literal `require`, `getfenv`, `setfenv`, `loadstring`, `rawget(_G`, `_G[` so the closure is sound by construction; proven by `import-nonliteral` |
| T-1-21 | Tampering (guard evasion) | lint suppression comments in pure zones | mitigate | R3b fails on `selene: allow`, `--# selene`, `--!nocheck`, `--!nonstrict`; proven by `engine-suppressed` |
| T-1-07 | Information disclosure | `src/client`, `src/shared` | mitigate | R5 bans the literals `SpoonDefaultSpot`, `DecoyAnchor`, `SeekerSpawn`, `HiderSpawn` outside server code; proven by `secret-name` |
| T-1-05 | Elevation of privilege | client-to-server entry points | mitigate | R4 confines `OnServerEvent` / `OnServerInvoke` / `RemoteFunction` / `UnreliableRemoteEvent` / `FireClient` / `FireAllClients` to `NetServer.luau` and `FireServer` to `ClientNet.luau`; proven by `net-hygiene` |
| T-1-12 | Tampering (of the gate itself) | `check-guards` false negatives and false positives | mitigate | `import-clean` must exit 0 so a guard that fires on everything also fails the suite; the whole script body is wrapped so an internal error exits non-zero rather than 0 |
