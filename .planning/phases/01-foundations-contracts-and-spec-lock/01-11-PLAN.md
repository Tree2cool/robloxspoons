Rules you must not break:
- **The pure-zone list is captured once, asserted non-empty, and reused.** The earlier draft
  inlined `$(lune run ... --print-zones)` directly in two `run:` lines. If that substitution ever
  produced nothing — a renamed script, a changed flag, a `zones.luau` edit — the two commands would
  degrade to `selene --config selene.pure.toml` (no paths) and `luau-lsp analyze ... scripts tests`
  (pure zones silently absent), and **both steps would still exit 0**. The FOUND-06 gate would be
  gone while CI stayed green. The dedicated `Pure zone list` step with `test -n "$zones"` is what
  makes that impossible; plan 01-03 additionally makes `--print-zones` exit non-zero on an empty
  list, so either layer alone catches it.
- `on: push` with no `branches` filter is deliberate (D-02: every push to any branch).
- `permissions: contents: read` is the whole token scope this workflow needs (ASVS V14).
- The action is pinned by **commit SHA**, not by tag, because a tag can be moved (T-1-08).
- Never add `--allow-warnings` to Selene and never add `--formatter plain` to luau-lsp.
- If the `ubuntu-latest` label or `actions/checkout@v7` has moved on, use the current one and
  record the change (assumption A8).

  4. `FireServer("NotAnIntent", {})` — unknown intent. Expected: rejected before any state is
     allocated.
  5. `FireServer("Ping", { nonce = 1 })` about ten times quickly — expected: a rate-limit rejection
