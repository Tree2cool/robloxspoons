**ORDERING CONTRACT (read this first).** This task creates **three** files, not four.
`tests/harness/Fuzz.luau` is created in **task 3**, together with `src/server/engine/Rng.luau`
that it depends on. That split is deliberate: `Fuzz` needs `Rng`, and a `Test.luau` that required
`Fuzz` would leave an unresolvable require in the tree between this task and task 3 — which both
`luau-lsp analyze ... tests` here and `lune run tests/run.luau` in task 2 would fail on.

So:
- **`Test.luau` is the sole owner of the `FuzzOpts` and `FuzzDriver` types.** `Fuzz.luau` imports
  them from `Test.luau` in task 3, never the other way round.
- **`Test.luau` requires nothing at all** — no `Fuzz`, no `Rng`, no `@lune/*`.
- The fuzz driver is **injected** into `Test.new`. Until task 3 installs it, `t.fuzz` registers a
  case that fails loudly.

`tests/harness/Test.luau` — the API every later spec consumes. Export this exact shape so no
later plan has to guess:

```lua
--!strict
export type Case = { name: string, fn: () -> () }

-- Owned HERE, not in Fuzz.luau, so Test.luau has zero requires (see ORDERING CONTRACT).
export type FuzzOpts = {
	seed: number?,
	iterations: number?,
	gen: (rng: any, i: number) -> any,
	check: (value: any) -> (),
}
export type FuzzDriver = (name: string, opts: FuzzOpts, seed: number) -> ()

export type Options = { seed: number?, fuzzDriver: FuzzDriver? }

export type Runner = {
	cases: { Case },
	todos: { string },
	seed: number,
	test: (name: string, fn: () -> ()) -> (),
	todo: (name: string) -> (),
	equal: (actual: any, expected: any, message: string?) -> (),
	deepEqual: (actual: any, expected: any, message: string?) -> (),
	truthy: (value: any, message: string?) -> (),
	falsy: (value: any, message: string?) -> (),
	contains: (haystack: string, needle: string, message: string?) -> (),
	throws: (fn: () -> (), needle: string?) -> (),
	fuzz: (name: string, opts: FuzzOpts) -> (),
}

local function new(options: Options?): Runner
	-- seed defaults to 1; tests/run.luau passes --seed through
end
```

Rules for the implementation:
- `test(name, fn)` only **registers** the case. `tests/run.luau` executes them, so the runner owns
  pass/fail accounting and output.
- Assertions signal failure by `error(message, 0)` — `run.luau` wraps each case in `pcall`.
- `equal` must print both values: `string.format("expected %s, got %s", tostring(expected), tostring(actual))`.
  Compare with `==` only (no deep compare); add `t.deepEqual` using a recursive table walk with a
  depth cap of 8 — map and validator specs need it.
- `todo(name)` appends to `todos` and never fails. The spec-lock entries in plan 01-06 use it.
- `contains` uses `string.find(haystack, needle, 1, true)` (plain find, no patterns).
- `fuzz(name, opts)` registers a normal case named `name` whose body calls
  `options.fuzzDriver(name, opts, runner.seed)`. When `options.fuzzDriver` is `nil`, the registered
  case body is `error("fuzz driver not installed", 0)` — a loud failure, never a silent skip, so a
  future refactor that drops the wiring in `tests/run.luau` breaks the suite instead of quietly
  running nothing.

```lua
export type Scheduler = {
	nowDeci: () -> number,
	delay: (seconds: number, fn: () -> ()) -> (() -> ()),
}
export type FakeScheduler = Scheduler & {
	advance: (seconds: number) -> (),
	pending: () -> number,
}

```
Implementation notes:
- Internal time is kept in **integer deciseconds** (`CLAUDE.md` rule 5). `advance(seconds)` adds
  `math.floor(seconds * 10)` deciseconds. `nowDeci()` returns that integer.
- `delay(seconds, fn)` records `{ dueDeci = nowDeci() + math.floor(seconds * 10), fn = fn, cancelled = false }`
  and returns a cancel closure. When `Options.cancelIsNoop` is true the returned closure does
  nothing — this is what lets plan 01-06 prove the round-ID token guard **independently** of
  `task.cancel`.
- `advance` fires all non-cancelled entries with `dueDeci <= nowDeci()` in ascending `dueDeci`
  order, each exactly once, removing them before invoking so a callback that schedules more work
  cannot re-fire itself.

**`tests/run.luau`** — the single test entrypoint. `--!strict`. Behaviour:

- Parse `process.args`: `--filter <substring>` (match against `"<specPath>::<caseName>"`),
  `--root <dir>` (default `tests`), `--seed <number>` (passed to `Fuzz`).
- Discover spec files by recursing `--root` with `fs.readDir`/`fs.isDir`, collecting files whose
  name ends in `.spec.luau`. **Skip any path containing `/fixtures/`** unless `--root` itself
  points inside a `fixtures` directory — the guard, purity, trap and meta fixtures are
  deliberately broken and must never be swept into the normal run (research Pitfall 3).
- Convert each discovered path to a require string relative to `tests/run.luau`: strip the leading
  `tests/` and prefix `./` (e.g. `tests/engine/rng.spec.luau` → `"./engine/rng.spec.luau"`), then
  `require` it. Each spec module returns `function(t: Runner) ... end`; call it with a fresh runner
  built as `Test.new({ seed = seed })` to register cases, then execute each case in `pcall`.
  **Do not require `tests/harness/Fuzz.luau` here** — it does not exist yet. Task 3 adds the
  `fuzzDriver = Fuzz.driver` field to this exact `Test.new` call, so leave the options table in a
  shape that takes one more key without restructuring.
- **A spec module that loads but registers ZERO cases and ZERO todos is a FAILURE**, reported as
  `FAIL <path>::<no cases registered>` and counted in `M`. Without this, a typo in a spec body
  (`return function(t) end`, a mis-named `t.test`, an early `return`) silently disables an entire
  area while the suite still reads green — the same vacuity the meta-test exists to prevent.
- Print one line per case: `ok   <path>::<name>` / `FAIL <path>::<name>` followed by the indented
  error, and `todo <path>::<name>` for todos. Finish with
  `N passed, M failed, K todo in X.XXs` (duration from `os.clock()`).
- `process.exit(1)` if `M > 0`, if a spec module itself throws while loading, if any discovered
  spec registered nothing, or if **zero** specs were discovered (an empty run must not look green).
  `process.exit(0)` otherwise.
- Todos never fail the run but are always printed and counted.

Fallback if Lune rejects a runtime-computed require string (it is expected to accept one, but
this has never been executed): generate `tests/_manifest.luau` containing literal
`require("./area/x.spec.luau")` entries plus a spec that fails when the manifest is stale relative
to disk discovery. Record which path was taken in the SUMMARY. Do **not** fall back to
`luau.load`, which would break the specs' own relative requires.

`src/server/engine/Rng.luau` — **xorshift32 using `bit32`**. Do not use mulberry32, PCG32 or any
multiply-based 32-bit generator: Luau numbers are doubles and lose precision above 2^53, so a
32-bit multiply silently produces wrong values. `bit32` operations are already truncated to 32
bits, which is why xorshift is correct here.

```lua
--!strict
-- Pure, synchronous, Roblox-API-free (FOUND-06). xorshift32 via bit32: no multiplies, so no
-- double-precision loss. Deterministic from a seed so fuzz failures are reproducible.
export type Rng = {
	nextUint: (self: Rng) -> number,
	nextNumber: (self: Rng) -> number,
	nextInt: (self: Rng, lo: number, hi: number) -> number,
}
```
Implementation requirements:
- state is a 32-bit unsigned integer; `new(seed: number)` must reject a zero/non-integer seed by
  normalising it (`seed = bit32.bor(seed, 0); if state == 0 then state = 0x9E3779B9 end`) —
  xorshift32 is stuck at 0.
- step: `x = bit32.bxor(x, bit32.lshift(x, 13))`, `x = bit32.bxor(x, bit32.rshift(x, 17))`,
  `x = bit32.bxor(x, bit32.lshift(x, 5))`.
- `nextNumber` returns `nextUint() / 4294967296` (divide by 2^32, giving `[0, 1)`).
- `nextInt(lo, hi)` returns `lo + math.floor(nextNumber() * (hi - lo + 1))`, clamped so the
  `nextNumber() == 1 - eps` case cannot exceed `hi`.
- Only `bit32` and `math` may be referenced. No `warn`, no `task`, no `os`, no `game` — Selene's
  `luau` std does not define them and `selene --config selene.pure.toml` will deny them.
