<objective>
The 100,000-action fuzz suite: one stateful property whose iteration is a whole round, checking the
full four-bucket partition identity after every single action, across random pools, random seat
counts, random churn and deliberately illegal intents — and asserting its own coverage so it cannot
look green while testing nothing.

Purpose: this is the phase's load-bearing conservation proof (ROADMAP Phase 2 success criterion 1)
and it closes a carried Phase 1 todo — "the fuzz harness has only ever run toy properties at 200
iterations, never the 100k-action scale Phase 2 needs". Research §11.3 names the two specific ways a
fuzz suite looks green while verifying nothing: a generator bug that shortens rounds, and a
generator that never emits a completion, a mid-pass departure or an illegal intent. Both need
explicit assertions, because Phase 1 verification already found two checks that could not fail at
all. Research §11.1 measured the full identity scan at 343,502 actions/s, so 100k actions costs
~0.3s and there is no reason to tier it.
Output: one spec, one fuzz case, ~0.3-1.0s of runtime, and a coverage table that fails loudly.
</objective>

**One iteration is one whole round** (research §11.2). `gen(rng, i)` returns a PLAN, not a state:

```luau
{
	i = i, -- the iteration index; `check` needs it to know when to assert the coverage totals
	roundSeed = rng:nextUint(),
	seatCount = rng:nextInt(2, 9), -- 2..9 seats = N 3..10 players (seatCount = N - 1, amendment A3)
	k = rng:nextInt(1, 2), -- k >= 1 is mandatory (amendment A4); k = 0 is plan 02-10's negative result
	jokers = rng:nextInt(0, 2),
	jokerMode = if rng:nextNumber() < 0.5 then "Wild" else "Blocker",
	churnChance = 0.01, -- per action: a random live seat is Disconnected or Benched
	illegalChance = 0.12, -- per action: a deliberately illegal intent is attempted
}
```

`check(plan)` builds the round with `Engine.newRound` from `Rng.new(plan.roundSeed)` and drives it.
**The round must be a pure function of `plan`, and `plan` a pure function of the base seed and `i`.**
Say that in a comment: the driver prints the base seed and the iteration, which only reproduces the
failure if that holds, and CONTEXT requires a failing trial to paste straight into a unit test.

**Every error message `check` raises must include `plan.roundSeed`, `plan.i`, `plan.seatCount` and
the pool.** The driver adds the base seed and the iteration; the round seed is what makes the
failure a one-line reproduction.

Round driver loop, until the round is over (`liveCount == 0`, or completions reach `seatCount - 1`,
or a per-round action cap of 4,000 is hit — error on the cap, because a 2..9 seat round cannot
legitimately need that many actions and a runaway loop would otherwise just make the suite slow):

1. With probability `illegalChance`, build ONE deliberately illegal intent, cycling through the
   seven kinds so every code is attempted across the run: draw at 5, pass at 4, pass a card you do
   not hold, pass a card sitting in an inbox, act on a removed seat, seat index 0 or `seatCount + 1`,
   card ID 0 or `totalCards + 1`. Record `Invariants.hash(state)` first, apply, then assert all of:
   `result.ok == false`, `result.reject` is the EXPECTED code for that construction (not merely
   non-nil), `#result.events == 0`, and the hash is unchanged. Count the code in `rejectCounts`.
   Research §11.3: a rejection that mutates state is worse than one that errors, and a code asserted
   only as "some rejection" would let a single catch-all branch pass.
2. Otherwise pick a live seat with a legal action, uniformly, and apply it: `Draw` when `#hand == 4`
   and `#inbox > 0`, `Pass` of a uniformly random held card when `#hand == 5`. Count each returned
   event by kind, and count completions by shape (`naturalsUsed == 4`, `== 3`, `== 2`) so the joker
   paths are separately visible.
3. With probability `churnChance`, remove a uniformly random live seat with
   `Disconnected` or `Benched` (alternate, so both causes accumulate). Count the cause, and count
   the ring-shrink milestones: dealer removed, ring reduced to 2, ring reduced to 1, ring emptied.
4. **After EVERY action** — accepted or rejected — call `Invariants.check(state)` and error with the
   violation name plus the reproduction data if it is not clean. Full identity scan every action, no
   tiering (research §11.1: 1.7x the cost of counters alone, and 100k actions is ~0.3s).
5. If no live seat has a legal action while `Invariants.circulation(state) >= 1`, error: that is the
   liveness invariant and it means the ring is corrupt (research §5).
6. Accumulate `totalActions` and all the coverage counters in SPEC-LEVEL locals (closed over by
   `check`), not in the plan.

Set `opts.iterations = 500` and `opts.seed = 20260203` explicitly. At ~250 actions per round
(research §11.2) that is ~125,000 actions, comfortably over the 100,000 floor with margin for the
shorter 2-seat rounds. Add a comment with the arithmetic so a future edit to the round length is
forced to reconsider the iteration count.
