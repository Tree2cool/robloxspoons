<objective>
One pure function, `nextSeatOrder`, that ranks the seated seekers for the next round. The dealer is
its head. It answers every input CARD-05 and CARD-06 leave unspecified, deterministically, with no
RNG after round 1.

Purpose: research §8.1 shows CARD-05 ("dealer is the previous round's first finder, falling through
to the highest-placed finisher actually seated") and CARD-06 ("finishers in find order, then the
empty-handed seeker, then everyone else") collapse into a single ranking, because the hider is not
seated and therefore the highest-placed seated finisher IS the head of the seat order. Two rules
implemented once cannot disagree. Research §8.2 then lists five reachable inputs neither
requirement covers, all of which show up in exactly the rounds the simulator hunts.
Output: `SeatOrder.luau` plus a table-driven corpus that locks all five.
</objective>

export type PlayerId = number

export type SeatOrderInput = {
	round: number, -- 1-based; round 1 takes the seeded-shuffle path
	roster: { PlayerId }, -- players present NOW, in join order. The source of truth for "still in the server"

	previousHider: PlayerId?, -- last round's hider
	rng: any?, -- an Rng; REQUIRED when round == 1, ignored otherwise
}

nextSeatOrder: (input: SeatOrderInput) -> { PlayerId }
dealerOf: (order: { PlayerId }) -> PlayerId?

  <action>
Create `src/server/engine/SeatOrder.luau` exporting `nextSeatOrder` and `dealerOf`.

**The total order (locked here — research §8.2's recommendation, extending SUMMARY.md Open
Question 6's default, which the ROADMAP marks as resolved in this phase).** Build the result by
concatenating these buckets in order; within a bucket, use the stated key; the final tiebreak
everywhere is `playerId` ascending (`playerId` is the Roblox `UserId`, so it is a stable total
order and never ties):

| # | bucket | key within the bucket |
|---|--------|----------------------|
| 1 | finishers | position in `previousFindOrder` |
| 2 | non-finishers who were seated last round | their index in `previousSeatOrder` ascending |
| 3 | the previous hider | single entry |
| 4 | joiners (in no previous list) | index in `roster` (join order) |

Rules that make it total and crash-free:
1. **Filter against the live roster BEFORE bucketing, never after.** A `previousFindOrder` entry for
   a player who has left must not occupy a bucket slot; otherwise `order[1]` can be a departed
   player and the dealer is a ghost (research §8.2 row 5).
2. **Remove `hiderId` from every bucket.** The hider does not play cards (02-CONTEXT.md amendment
   A3) and the card table has 9 seat anchors against a 10-player cap.
3. **Zero finishers is not a special case.** Bucket 1 is empty and `order[1]` becomes the head of
   bucket 2. This is reachable in every round that hits the 300s cap, which is exactly what the
   simulator hunts (research §8.2 row 2, OQ-F).
4. **Two or more empty-handed seekers is not a special case either.** CARD-06's "the empty-handed
   seeker" is singular only in a clean round where `N-2` of `N-1` seekers finish. Bucket 2 is a
   LIST with a defined key. Never index "the" non-finisher (research Pitfall 5).
5. **Round 1** takes the same function: buckets 1-3 are empty, so everyone is a joiner, and the
   result is a seeded Fisher-Yates shuffle of `roster` minus the hider using
   `input.rng:nextInt(lo, hi)`. If `round == 1` and `input.rng == nil`, `error("SeatOrder: round 1 requires an rng")`
   — a silent `math.random` fallback would make round 1 unreproducible and break every seeded
   simulator trial. For `round > 1` the function uses NO randomness at all; assert that by never
   touching `rng` on that path.
6. **De-duplicate.** A player may appear in both `previousFindOrder` and `previousSeatOrder`; each
   player appears in the result exactly once. Returning a duplicate would seat one player twice.
7. `dealerOf(order)` returns `order[1]`, or `nil` for an empty order. It exists so no caller writes
   `order[1]` inline and nobody can later add a second dealer rule. Add a header comment: **the
   dealer is the head of the seat order, always — there is no separate dealer rule** (research
   §8.1), because two rules implemented separately will eventually disagree.

Input validation: ignore a non-number or non-integer entry in any input list rather than erroring
(a malformed roster must not crash a round), but `error()` loudly if the resulting order is empty
while `roster` minus the hider is non-empty — that would mean a bug in the bucketing, and a nil
dealer is a crash one layer up (research §8.2 row 4).

The module takes no clock, no Roblox API and no state. It is a pure ranking function, which is what
makes the corpus in task 2 exhaustive rather than representative (research §8.3).

registering `t.test(case.name, ...)` that asserts `t.deepEqual(SeatOrder.nextSeatOrder(case.input), case.expected, case.why)`

a corpus whose failure message does not say WHICH rule was violated sends the next reader back to
the source.

The corpus must contain at least these rows, and each row's `why` must name the rule:

1. **first finder is the hider** — `previousFindOrder = {7, 3, 9}`, `hiderId = 7`,
   `roster = {3, 7, 9, 11}`. Expect the dealer to be 3. Why: "CARD-05 falls through to the
   highest-placed finisher actually SEATED, and the hider is not seated".
2. **zero finishers last round** — `previousFindOrder = {}`. Why: "bucket 1 is empty, so the dealer
   is the head of 'everyone else' by previous seat index; this is reachable in any capped round".
3. **two or more non-finishers** — a roster where 3 players finished nothing. Why: "CARD-06's
   'the empty-handed seeker' is singular only in a clean round; bucket 2 is a list with a key".
4. **a find order containing a departed player** — `previousFindOrder = {12}` with 12 absent from
   `roster`. Why: "the find order is filtered against the live roster BEFORE the head is taken".
5. **no previous finisher is still in the server (mass leave)** — every entry of
   `previousFindOrder` and `previousSeatOrder` has left; `roster` is all joiners. Why: "the function
   must still produce a dealer; a nil dealer is a crash one layer up".
6. **the previous hider rejoins the table** — sorts after all seated non-finishers, before joiners.
7. **a joiner** — present only in `roster`; sorts last, by join order.
8. **userId tiebreak** — two players with identical bucket keys (both joiners added in the same
   position is impossible, so use two players absent from all previous lists and assert the roster
   order is preserved, then a second case where bucket keys tie and ascending `playerId` decides).

Then these standalone cases:

9. `"round 1 is the same function with a seeded shuffle"` — same seed twice gives the identical
   order; a different seed gives a different order (assert both, or the shuffle could be a no-op);
   the result is a permutation of `roster` minus the hider (assert length and set membership).
10. `"round 1 without an rng errors rather than falling back"` — `t.throws(..., "round 1 requires an rng")`.
11. `"rounds after 1 use no randomness"` — call `nextSeatOrder` for `round = 2` twice with NO `rng`
    field at all and assert the orders are deepEqual and that it did not error. A function that
    reached for the rng on this path would crash here.
12. `"the hider never appears in the order"` — for every corpus row, assert the hider is absent from
    the result. Write it as a loop over `CASES` so a new row cannot forget it.
13. `"no player appears twice"` — loop over `CASES`, assert the result has no duplicate entries.
14. `"the order holds every eligible roster member"` — loop over `CASES`, assert
    `#result == #roster - (1 if hider in roster else 0)`. This is the case that catches a bucketing
    bug that silently drops a player: the engine would then deal to fewer seats than there are
    seekers, and nothing else in the phase would notice.
