<objective>
Completion detection: given a 5-card hand, the round's `rankOf` map and the `EngineConfig`, decide
whether four of a kind exists and, if so, exactly which four cards leave — naturals before jokers.
Both joker modes are the same function selected by a config value, so CARD-10 and CARD-12 both ship
and both stay under test from day one.

Purpose: research §3.3 proves naturals-first is not merely the spec-locked choice but the
solvability-optimal one — it simultaneously minimises cards stranded and jokers consumed. The same
section proves that at `j <= 2` no 5-card hand can satisfy two ranks, so completion needs **no
tiebreak**; a test should assert that uniqueness rather than assume an arbitrary pick is safe.
Research §3.5 then shows the Wild/Blocker switch is not a free flag — at `k = 0` it is a cliff from
0% to 97.4% stalls — which is why the switch must be an `EngineConfig` value that both variants
exercise in the same process, never a module-level constant.
Output: `Hand.luau` and a spec that proves the uniqueness theorem by enumeration and falsifies it at
`j = 3`.
</objective>

export type Completion = {
	rank: Types.Rank, -- the NATURAL rank completed; never JOKER_RANK

  <action>
Create `src/server/engine/Hand.luau`, requiring only `./Types`.

**`groupsOf(rankOf, hand)`** — returns `(naturalCounts, jokerCount)`. Keys of `naturalCounts` are
natural ranks only; `Types.JOKER_RANK` is never a key. Used by `qualifyingRanks`, by the spec, and by
plan 02-09's greedy bot (which must not reimplement it).

**`qualifyingRanks(rankOf, hand, mode)`** — the ranks this hand could complete:
- `Wild`: every natural rank `r` with `a = naturalCounts[r] >= 1` and `a + jokerCount >= 4`.
  The `a >= 1` clause matters: a set must be anchored by at least one natural, because the rank of
  an all-joker set is undefined. Research §3.3 proves an all-joker set is unreachable for `j <= 2`
  anyway (a 5-card hand can hold at most 2 jokers), so this clause is belt-and-braces — say that in
  a comment, and say that it reopens at `j >= 3`.
- `Blocker`: every natural rank `r` with `naturalCounts[r] == 4`. Jokers contribute nothing. This is
  CARD-12 and it is the SAME function with a different branch, not a second module.
Return the ranks sorted ascending so the result is deterministic and a test can deepEqual it.

**`detectCompletion(rankOf, hand, mode)`**:
1. `error("Hand.detectCompletion: hand must hold 5")` unless `#hand == Types.MAX_HAND`. CARD-01's
   hand-size invariant is `#hand` in {4, 5} and completion is checked only on draw, so a call at any
   other size is a caller bug and must be loud, not silently `nil`.
2. `local qual = qualifyingRanks(...)`. If `#qual == 0`, return `nil`.
3. If `#qual >= 2`, `error("Hand.detectCompletion: completing rank is not unique (...)")` listing the
   ranks. This is a **tripwire, not a tiebreak**: research §3.3 proves that for `j <= 2` no 5-card
   hand satisfies two ranks (4+4 needs 8 cards; 3+1j twice needs 6; 2+2j plus anything leaves the
   other at <= 3). Writing a tiebreak here would silently paper over a `j >= 3` config or a
   `rankOf` corruption. Task 2 proves the branch can fire.
4. Naturals-first selection for `r = qual[1]`, implementing research §3.3's table
   (4 naturals strands 0 and spends 0 jokers; 3+1 strands 1 and spends 1; 2+2 strands 2 and spends 2
   — so taking the most naturals available is optimal on BOTH axes simultaneously):
   - `naturalsUsed = math.min(naturalCounts[r], 4)`
   - `jokersUsed = 4 - naturalsUsed`
   - `retired` = the `naturalsUsed` card IDs of rank `r` with the lowest IDs, in ascending order,
     followed by the `jokersUsed` joker IDs with the lowest IDs, in ascending order
   - `fifth` = the one hand card not in `retired`
   Sort within each group by ascending card ID so the selection is deterministic: a failing
   simulator trial must reproduce exactly from its seed, and an arbitrary pick would make a replay
   diverge.
5. Assert `#retired == 4` and that `fifth` is not in `retired` before returning. Cheap, and it
   catches an off-by-one in the ID selection at the one place it would otherwise become a card-loss
   bug four layers downstream.

Header comment must state, with reasons:
- Four of a kind is checked ONLY on draw (CLAUDE.md), so this module never sees a 4-card hand except
  as a caller bug.
- `jokerMode` arrives in `EngineConfig` as a VALUE. There is no module-level constant and no
  `if SHIP_WILDS then` anywhere: both variants must be runnable in the same process so the Gate G1
  sweep can clear the chosen pool in both positions (research §3.5 — at `k = 0` the flag is a cliff
  from 0% to 97.4% stalls, so a flag only tested in one position is not a fallback).
- Naturals-first is solvability-optimal, not just spec-locked (research §3.3).
- Total cards stranded per round is bounded by `j <= 2`, because each joker completion consumes at
  least one joker.
