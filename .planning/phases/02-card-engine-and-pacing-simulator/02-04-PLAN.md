<objective>
The pool and the deal: build the card multiset, shuffle it so a card ID is a deck position and not a
rank, deal four cards to every seat with the rest under the dealer, and reject any deal that hands
someone a complete or wild-completable opening hand (CARD-09) — with an assertion that the rejection
actually fired.

Purpose: research §10 measured rejection sampling at 1.0-1.34 attempts (max 4 in 400 trials), so the
honest implementation is cheap. It also names the trap: **a re-shuffle loop whose completeness
predicate always returns false looks identical to a correct one** — same output, always one attempt,
suite green, and the bug CARD-09 exists to prevent ships. Two assertions close it: a crafted deck
that forces a rejection, and a corpus assertion that the rejection counter is > 0.
Output: `Pool.luau` and a spec where the deal check has been proven capable of firing.
</objective>

**The deal layout is locked here and every later plan assumes it:**
- `totalCards` (T) `= 4 * ranks + jokers`
- seat `s` (1-based) is dealt card IDs `(s - 1) * 4 + 1` through `s * 4`
- the dealer is seat 1, and its inbox holds IDs `seatCount * 4 + 1` through `T`, in ascending order
- so at the deal every circulating card sits in the dealer's inbox and every other inbox is empty
  (research §3.8), and the start-up ramp advances one seat per draw+pass pair
- the deal is random because `rankOf` is a fresh shuffle, NOT because the ID assignment moves

Create `src/server/engine/Pool.luau`, requiring `./Types` and `./Rng`.

**`validate(config, seatCount)`** — returns `(ok, reason)` with the reason drawn from exactly four
locked strings (tests assert the string, so never reword one):
- `"BadConfig"` — `ranks`, `jokers` or `seatCount` is not a non-negative integer, `jokers < 0`,
  `seatCount < 1`, or `jokerMode` is neither `"Wild"` nor `"Blocker"`
- `"RanksBelowSeats"` — `ranks < seatCount`. Research §3.1 Claim 2: the round needs `seatCount - 1`
  completions and each completion damages exactly one rank, so `ranks >= seatCount` is what keeps a
  fully intact rank available for the last required completion. Below it the theorem does not hold.
- `"TooManyJokers"` — `jokers > Types.MAX_JOKERS`. Research §3.3 proves the completing rank is
  unique and the all-joker set is unreachable only for `j <= 2`; at `j >= 3` both proofs reopen, so
  the engine refuses rather than silently invalidating its own uniqueness assertion.
- `"DeadPool"` — `circulationOf(config, seatCount) < 1`. At `k = 0, j = 0` every seat holds exactly
  4, no inbox is ever non-empty, no draw is ever legal, and four-of-a-kind is only checked on draw:
  a **provable instant deadlock**, measured at 100% stall for every N from 3 to 10 (research §3.1
  corollary, amendment A5). This cell must be excluded by an asserting result, never by a silent
  skip — hence a named reason rather than a crash.

**`circulationOf(config, seatCount)`** — `4 * (config.ranks - seatCount) + config.jokers`. One line,
and it is the whole of CARD-04: research §4.1 shows circulation is exactly constant under draw, pass
and completion and only ever grows (+4 per non-completing removal), so "the deck never runs dry" is
`circulation >= 1` forever. **Write no deck-refill, reshuffle or deck-exhaustion path anywhere.**
Research §14: a refill path would be dead code that hides a conservation bug.

**`shuffledRanks(config, rng)`** — build the multiset `{1,1,1,1, 2,2,2,2, ..., ranks x4}` followed by
`config.jokers` copies of `Types.JOKER_RANK`, then Fisher-Yates in place with
`rng:nextInt(i, n)` descending. The returned table IS `rankOf`: index = card ID, value = rank. A
card ID is therefore a shuffled deck POSITION and the ID -> rank mapping is re-randomised every
round, so an ID that ever leaks to a client carries no rank information (CLAUDE.md rule 3, research
Pitfall 6). Add that reason as a comment: allocating IDs in deck-build order would make
`id 7 => rank 2` for the whole game, and it costs nothing to close the class instead of the instance.

**`openingHandIsBad(rankOf, handIds, mode)`** — true when this 4-card hand must be re-dealt:
- count naturals per rank and count jokers held
- Wild mode: bad if any rank has 4 naturals, OR any rank has `a` naturals with `a >= 1` and
  `a + jokersHeld >= 4` (this covers 3+1 and 2+2 — research §3.3 proves those are the only wild
  completions possible for `j <= 2`)
- Blocker mode: bad only if some rank has 4 naturals; a joker can never complete a set, so
  3 naturals + 1 joker is a legal opening hand in Blocker mode and an ILLEGAL one in Wild mode
Check the 4-natural case and the wild-completable case as **separate conditions**, not one collapsed
expression: research §10 warns that a predicate which only checks `n == 4` passes the obvious test
and silently ships exactly the bug CARD-09 exists to prevent.

**`deal(config, seatCount, rng)`** — `error()` with the reason string if `validate` fails (a round
must never start on an invalid pool). Then loop up to `Types.MAX_DEAL_ATTEMPTS`:
`rankOf = shuffledRanks(...)`; for each seat `s` in `1..seatCount`, test
`openingHandIsBad(rankOf, {(s-1)*4+1, ..., s*4}, config.jokerMode)`; accept on the first permutation
where no seat is bad. Return `(rankOf, attempts)`.

On exhausting 64 attempts: `error("Pool.deal: no legal deal in 64 attempts (ranks=..., jokers=..., seats=...)")`.
Research §10: the measured max over ~14,000 deals was 4 attempts, so 64 is roughly 50 standard
deviations away and reaching it means a broken predicate, not bad luck. **Do not write a "repair"
path that edits a bad deal** — it would change the deal distribution for the tightest tables, which
are exactly the 3-player rounds.

`attempts` is returned, not logged, because the corpus assertion in task 2 needs to see it. Add a
comment saying so: without a visible counter the rejection loop is unfalsifiable.
