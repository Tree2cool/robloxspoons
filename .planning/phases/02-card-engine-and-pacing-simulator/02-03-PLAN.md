<objective>
Make Non-Negotiable Rules 5 ("the server is the only clock") and 6 ("no yields inside state
mutations") enforced instead of merely stated, by extending `check-guards` rule R3's banned
constructs for pure zones with `coroutine` and the `os.` namespace — and prove both bans can fail.

Purpose: research §1 ran a pure-zone fixture using `coroutine.yield`, `coroutine.resume`, `os.clock`
and `os.time` through the repository's own `selene.pure.toml` and got **0 errors, 0 warnings**.
`selene.pure.toml` sets `std = "luau"`, and `coroutine.*` and `os.*` are standard Luau, so today an
engine module can yield mid-mutation and read a real clock while all 14 gates stay green. The three
pure zones contain neither construct today, so the ban is zero-churn now and expensive after the
engine is written. This plan is scheduled in wave 1 for exactly that reason: it lands before the
engine does, so the engine is born under the rule.
Output: two new R3 bans, two mutation fixtures, two new `guards.spec` rows.

**Scheduling note (why this plan is wave 1 ALONE).** It edits `scripts/ci/check-guards.luau`, which
every other plan's `<verify>` invokes. A sibling plan running `lune run scripts/ci/check-guards.luau`
while this one is mid-edit would fail on a half-written guard script and report a defect that does
not exist. Plans 02-01 and 02-02 therefore depend on this plan rather than running beside it, and the
engine is born under the rule — which is the reason this plan was scheduled first in the original
plan set anyway.
</objective>
