<objective>
The ring: a circular doubly-linked list over a fixed seat array, the pass/draw primitives, and the
one generic `removeSeat` that handles completion, disconnect and AFK identically — including the two
cases the project rules do not currently cover (the ring shrinking to 1, and the sole seat
completing with no successor to route to).

Purpose: research §6 shows the wrap needs no special case because seat `m`'s `next` IS the dealer,
so CARD-04's "the last seat's passes land beneath the dealer's deck" is just "append to the tail of
`next`'s inbox" — and the test that proves there is no hidden branch is to run everything at `m = 2`,
where the dealer is simultaneously the only `prev` and the only `next`. Research §7 then enumerates
six removal edge cases, and §7.3 finds a genuine collision: Rule 8 says a removed seat's cards go to
the successor and are never destroyed, but when the last seat completes there is no successor. That
needs a `terminal` bucket, or "never destroyed" stops being literally assertable.
Output: `Ring.luau`, a ring spec, and a removal spec in which destroying a removed seat's cards is
shown to make the multiset unsatisfiable — the mutation proof the house standard requires.
</objective>

**Locked ordering decisions (research OQ-G and §7.3 — both were unspecified before this plan):**
1. **Dump order:** the departing seat's **hand first (ascending card ID), then its inbox in FIFO
   order**, all appended to the successor's inbox tail. This preserves the global chain order,
   because inbox cards arrived from upstream after the hand was assembled. Either choice is
   defensible; leaving it implicit is not, because it determines the successor's draw order and
   therefore replay determinism.
2. **No successor:** when the removed seat is the only live seat, its remaining cards move to
   `state.terminal` and the ring becomes empty (`liveCount = 0`, `head = 0`). Routing them to
   `self` would resurrect a dead seat; destroying them would break Rule 8. The partition identity
   counts `terminal`, so "never destroyed" stays literally assertable.

  <action>
Add `removeSeat(state, seatId, cause)` to `src/server/engine/Ring.luau`.

**One function, three causes, and the cause must never fork the routing.** CLAUDE.md rule 8: seat
removal is one generic operation used for completion, disconnect and AFK. Only `Completed` differs,
and only in what the CALLER did first (`Engine.apply` has already moved the four retired cards out
of the hand). Inside `removeSeat` the cause affects exactly one thing: `churnRemovals` is
incremented when `cause ~= "Completed"`. If the causes forked the routing, Rule 8 would hold on one
path and not another — and the disconnect path is the one nobody exercises by hand.

Steps, in this order:
1. `error()` if the seat does not exist or is not live. A double removal is a caller bug; silently
   returning would leave the ring and `liveCount` disagreeing.
2. Compute `routedTo = (liveCount > 1) and seats[seatId].next or nil`.
3. Build the dumped list: the departing `hand` sorted ascending, then the departing `inbox` in FIFO
   order (locked decision 1). Clear both containers on the departing seat.
4. If `routedTo ~= nil`, append the whole dumped list to `seats[routedTo].inbox` tail, in that order.
   Otherwise append it to `state.terminal` (locked decision 2, research §7.3).
5. Unlink: `seats[seats[seatId].prev].next = seats[seatId].next` and
   `seats[seats[seatId].next].prev = seats[seatId].prev`. **Write it exactly that way so a 2-ring is
   not a special case:** when `A.next == A.prev == B`, both assignments reduce to `B.next = B` and
   `B.prev = B`, which is correct — and it is the case a naive implementation breaks (research §7.1).
   Do not add an `if liveCount == 2` branch.
6. `seats[seatId].live = false`; `seats[seatId].next = seatId`; `seats[seatId].prev = seatId`
   (so a stale reference cannot walk back into the live ring); `liveCount -= 1`.
7. If `state.head == seatId`, set `head = routedTo or 0`. `head = 0` is the ring-emptied sentinel
   that `Invariants.check` already special-cases.
8. If `cause ~= "Completed"`, `counters.churnRemovals += 1`. Research §4.1: a non-completing removal
   adds exactly 4 to circulation (the departing hand's 4 resting cards become inbox cards), which is
   the formal statement of "churn makes the table looser, never tighter". A completion is net zero.
9. Return `(routedTo, #dumped)`.

**A 1-seat ring must be playable, not merely non-crashing** (research §7.2). `next == prev == self`,
so passing appends to your own inbox and drawing pops your own inbox — self-consistent and still
live. The sole remaining seat is the empty-handed seeker, and PROJECT.md awards a four-of-a-kind
bonus with zero find points to a seeker who completes but finds no spoon, so this is a shipping
state. Add that reason as a comment; otherwise someone will later "fix" it with an early return.

**Do not add a `destroyCards` parameter or any other path that discards cards.** The Rule 8 mutation
proof in task 3 performs the destruction from the test side, so no shipped code path can ever
destroy a removed seat's cards. Say that in the header.

Note for plan 02-07: `removeSeat` does NOT update `counters.rankInPlay` / `cnt`, because routing a
card to an inbox does not take it out of play. Only retirement (Engine, on completion) and the
terminal bucket change what is in play, and the terminal move happens here — so when `routedTo` is
nil, decrement `rankInPlay`/`jokersInPlay`/`cnt` for every dumped card. Make that the one counter
responsibility this function carries, and comment it: a card in `terminal` is accounted for but out
of play.
