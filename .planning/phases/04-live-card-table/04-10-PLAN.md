<objective>
The fixed-duration flourish driver: the CARD-18 seam Phase 7 plugs deck-skin animations into, and
the thing that guarantees no celebration can ever hold a finisher still.

Purpose, and why this is a fairness mechanism rather than a polish one:

- **D-32:** PROJECT.md requires **every** deal animation to have the same fixed duration so that
  none confers an advantage. An unequal-duration animation would be a **pay-to-win defect**, not a
  cosmetic bug. Defining the contract now is what makes it enforceable later instead of a retrofit.
- **D-30:** control returns to the finisher **instantly**. This is a *scoring* constraint, not a
  feel preference: find order drives SCORE-01..03, so any beat that holds the finisher still is
  literally taking points off them. **No celebration may block input.**
- **Checker FLAG F8, handed to the planner and resolved here:** the UI-SPEC's post-play scan ran
  only when `play` returned and at the cut-off, so an `Active` full-screen GuiObject created
  **mid-flight** could sink input for part of the 1.5 s — silently breaking D-30, which is what
  protects a finisher's score. The resolution is three-part: a **periodic** scan during the flight,
  a **ScreenGui-constrained parent** for the `Deal` kind, and an explicit **`DisplayOrder` below the
  hand**.

**The known limit, stated honestly and not papered over:** a *synchronous* infinite loop inside
`play` cannot be stopped in Luau. `pcall` bounds neither time nor yields. The defences are the
driver's own timer, the periodic scan, and code review of any registered flourish — not a runtime
guarantee. Phase 4 ships only the default flourishes, so the exposure is zero today and the
contract is what keeps it bounded when Phase 7 adds content.

Output: `Flourish.luau` and the CARD-17 gate.
</objective>

```luau
--!strict
local Card = require("../Config/Card")

export type Kind = "Deal" | "Completion"
export type Root = any  -- an opaque handle only the Surface understands

export type FlourishContext = {
	root: Root,
	kind: Kind,
	seat: number,
	isLocalSeat: boolean,
	durationSeconds: number,
	faces: { number },  -- PUBLIC ranks only, completion only; empty for Deal
}
export type Entry = { kind: Kind, play: (ctx: FlourishContext) -> () }

-- Everything Roblox-shaped, injected. The pure driver can therefore be run entirely in Lune, which
-- is the only reason tests (a)..(f) exist at all.
export type Surface = {
	createRoot: (kind: Kind) -> Root,
	destroyRoot: (root: Root) -> (),
	-- Every Active / Interactable descendant under `root`, as descriptions. Empty is clean.
	scan: (root: Root) -> { string },
	-- A pre-play census of every parent a flourish could plausibly reach.
	snapshot: () -> any,
	-- New instances outside `root` since the snapshot, as descriptions.
	diff: (snapshot: any) -> { string },
	destroyEscaped: (snapshot: any) -> number,
}
export type Thread = any
export type Scheduler = {
	nowDeci: () -> number,
	delay: (seconds: number, fn: () -> ()) -> () -> (),  -- returns a cancel function
	spawn: (fn: () -> ()) -> Thread,
	cancel: (thread: Thread) -> (),
}
export type Deps = {
	surface: Surface,
	scheduler: Scheduler,
	durationSeconds: number,       -- Card.FLOURISH_DURATION_SECONDS; the DRIVER's number
	scanIntervalSeconds: number,   -- Card.FLOURISH_SCAN_INTERVAL_SECONDS; F8
	registry: { [string]: Entry }, -- INJECTED. Phase 7 supplies skin flourishes; Phase 4 the defaults
	onViolation: (message: string) -> (),
}

export type Driver = {
	play: (self: Driver, kind: Kind, seat: number, isLocalSeat: boolean, faces: { number }) -> (),
	cancelAll: (self: Driver) -> (),
	activeCount: (self: Driver) -> number,
}
Flourish.new = function(deps: Deps): Driver

-- F8: the Deal kind is UI and must live inside a ScreenGui with an explicit DisplayOrder BELOW the
-- hand, so an Active object it creates cannot sit over the hand and sink a tap. The Completion kind
-- is 3D and lives under a Workspace folder. Carried as STRINGS, because this is a pure zone; plan
-- 04-19's Surface maps them.
Flourish.ROOT_SURFACE = { Deal = "ScreenGui", Completion = "Workspace" }  -- frozen
Flourish.DISPLAY_ORDER = Card.FLOURISH_DISPLAY_ORDER                      -- 5, below the hand's 10

-- The default "Plain" flourishes as KEYFRAME DATA, not as code: a pure zone cannot tween, and data
-- lets test (c) assert the totals arithmetically. Plan 04-19's Surface executes them.
Flourish.DEFAULTS = {
	Completion = { steps = { { name = "flip", seconds = 0.3 }, { name = "hold", seconds = 0.5 }, { name = "slide", seconds = 0.4 } } },
	Deal = { staggerSeconds = 0.1, cards = 4, settleBySeconds = 0.6 },
}  -- frozen
Flourish.totalOf = function(def: any): number  -- sums `steps`, or derives Deal's settle time
```

**`play`'s ordering is the contract. It must be exactly this, and the spec asserts the call order
through a recording surface:**

1. `root = surface.createRoot(kind)`
2. `snapshot = surface.snapshot()`
3. **arm the teardown** at exactly `durationSeconds` — `cancelTeardown = scheduler.delay(...)`
4. **arm the first periodic scan** at `scanIntervalSeconds`, re-arming itself while the flight is
   live (F8)
5. **only now** `thread = scheduler.spawn(function() entry.play(ctx) end)`
6. when `play` returns (observed by a flag the spawned wrapper sets), run one scan
7. teardown, once and only once: `scheduler.cancel(thread)`, `surface.scan(root)`,
   `surface.diff(snapshot)` and `surface.destroyEscaped(snapshot)`, then `surface.destroyRoot(root)`

Steps 3 and 4 **before** step 5 is the whole point: `pcall` bounds neither time nor yields, so a
flourish that yields or waits must be cancelled by the driver's own timer rather than by anything
the flourish cooperates with.

**Every scan result and every diff entry is reported through `onViolation` and the offending
instance is destroyed.** A violation is never silent and never fatal: a broken flourish must not
take the round with it.

**A flourish may:** create instances under `ctx.root` only. **A flourish may not:** create an
`Active` or `Interactable` GuiObject; read anything about hands, score or another seat; parent
anything outside `ctx.root`; or delay input, the `Completed` handler, the avatar standing or control
restoration. The first three are **enforced** by the scan and the diff. The fourth is enforced by
step 5's spawn plus plan 04-11's `Controls.onLocalCompleted` ordering, which destroys the overlay and
restores controls **before** the flourish starts.

**An unknown `kind`, or a `kind` with no registry entry, must be reported through `onViolation` and
must NOT throw** — a missing cosmetic cannot be allowed to break a completion, which is the moment
a score depends on.
