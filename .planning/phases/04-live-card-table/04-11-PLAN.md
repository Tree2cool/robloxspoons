<objective>
Two pure modules the renderer cannot be written without: every word the card HUD will ever show,
and the control-hiding state machine.

Purpose, UX-04 (D-08, D-09): hints follow the **last input actually used** and switch live, not the
device type at join. That handles a touchscreen laptop, a phone with a paired mouse, and someone
who picks up a controller mid-round. Keyboard accelerators are **additive** — the pointer path is
the guaranteed one and the keyboard must never become the only way to do anything.

Purpose, UX-02 (D-29), and the reason this is a seam rather than two lines of code:
**`PlayerModule:GetControls():Disable()` appears in NO official Roblox documentation and never
has.** A staff release post (2026-06-11) says the legacy endpoints "may no longer exist"; the
default player scripts flip to the Input Action System in **early 2027** and the legacy scripts are
removed **mid-2027**; DevForum reports from August and October 2026 say `GetControls()` is already
missing on opted-in places. So the mechanism lives behind one `hide`/`restore` seam with no other
API, the layers are chosen so **nothing in the default scripts is mutated** — and therefore nothing
needs restoring if a layer silently no-ops — and a source scan makes the forbidden identifiers
unusable.

Purpose, D-30: `onLocalCompleted` fixes the order **destroy overlay, restore controls, then start
the flourish**. The bottom-left thumbstick occupies the left pile's corner, so the overlay must be
*gone*, not faded; and a finisher held still is losing SCORE-01..03 points, so the restore cannot
queue behind a celebration.

This plan also writes the four UI-SPEC strings that exceed 34 characters, **rewritten rather than
truncated**, closing the copy half of checker FLAG F4.

Output: `Hints.luau`, `Controls.luau` and their two gates.
</objective>

export type InputKind = "Touch" | "Mouse" | "Keyboard" | "Gamepad"
export type State = "Hand5Idle" | "Selected" | "Hand4CanDraw" | "Hand4Empty" | "RightPileSink"

Hints.INPUT_KINDS = { "Touch", "Mouse", "Keyboard", "Gamepad" }                            -- frozen
Hints.STATES = { "Hand5Idle", "Selected", "Hand4CanDraw", "Hand4Empty", "RightPileSink" }  -- frozen
Hints.HINT: { [State]: { [InputKind]: string } }                                           -- frozen, 20 cells

-- D-09. Keyed by the NAME of a UserInputType, because a pure zone may not name an Enum. An
-- unmapped name returns nil, meaning "leave the hints alone": LastInputTypeChanged also fires for
-- Focus, Accelerometer, Gyro and TextInput, and switching the whole hint set on a gyro reading
-- would be a bug rather than responsiveness.
Hints.kindOf = function(userInputTypeName: string): InputKind?

-- Functions, not literals, wherever a number is interpolated: a call site that built the string by
-- concatenation would drift past the character cap with nothing to catch it.
Hints.MESSAGES = {
	countdown = function(owes: "Pass" | "Draw", secondsLeft: number): string,
	strike = function(strikes: number, owes: "Pass" | "Draw"): string,
	benched = function(): string,
	forcedPass = function(): string,
	stall = function(): string,
	waiting = function(): string,
}

	other = function(displayName: string): string,  -- truncates the name to NAME_BUDGET
	selfOut = function(): string,
}
Hints.NAME_BUDGET = 18

-- dependency, never a source edit. Returns the problems and the number of strings measured.
Hints.audit = function(t: {
	hint: any, states: { string }, kinds: { string },
	messages: any, callouts: any, maxChars: number, calloutMaxChars: number,
}): ({ string }, number)

`src/shared/Card/Controls.luau`:

```luau
export type Effects = {
	setTouchControls: (enabled: boolean) -> (),  -- 04-18: GuiService.TouchControlsEnabled
	bindSink: () -> (),                          -- 04-18: CAS BindActionAtPriority returning Sink
	unbindSink: () -> (),                        -- 04-18: CAS UnbindAction
	destroyOverlay: () -> (),                    -- 04-16: the hand ScreenGui, GONE not faded
	startFlourish: () -> (),                     -- 04-19: the driver's play()
}
export type Controls = {
	hide: (self: Controls) -> (),
	restore: (self: Controls) -> (),
	onLocalCompleted: (self: Controls) -> (),
	isHidden: (self: Controls) -> boolean,
}
Controls.new = function(effects: Effects): Controls
```

| Call | Effects, in exactly this order | Why |
|---|---|---|
| `hide()` when not hidden | `setTouchControls(false)`, `bindSink()` | graphics before the key sink, so a `Space` cannot jump in the gap |
| `hide()` when already hidden | **nothing** | idempotent |
| `restore()` when hidden | `unbindSink()`, `setTouchControls(true)` | **unbind first.** A sink still bound when controls return would eat the finisher's first key, and the finisher is mid-sprint |
| `restore()` when not hidden | **nothing** | idempotent and safe to call twice (research recommendation 3) |
| `onLocalCompleted()` | `destroyOverlay()`, then `restore()`'s two effects, then `startFlourish()` | D-30. The overlay must be gone before the thumbstick reappears under the left pile's corner, and the flourish is **last** so it can never delay either |

**`restore()` is not server-authoritative and must not pretend to be.** The server-side avatar hold
and `Dev*MovementMode` are plan 04-15's job and are the only security-relevant layer: a cheat client
can re-enable its own controls and walk off to hunt. The header must say so plainly, so nobody later
mistakes this module for the thing that keeps a seeker at the table.
