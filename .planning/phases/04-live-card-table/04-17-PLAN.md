<objective>
The hand, the card faces and both piles: the part of the screen a player actually touches.

Purpose: CARD-02 and CARD-15 are decided by the **hit model**, not by the animation. The slots are
invisible buttons laid out from `Layout.solve`, one per slot, **independent of z-order and of
whether a card is lifted**. That is what guarantees D-01's "tapping the selected card again lands on
the same strip" and what keeps every neighbouring strip above the 48 physical px floor.

Two accepted residuals from the UI-SPEC are implemented as written, not improved:

- **Checker FLAG F7:** hit strips snap to the final layout at the instant of commit while the visuals
  tween for 0.12 s, so the two disagree by up to 30 px for that window. **Accepted deliberately** —
  the alternative is a tap during the tween landing on a slot that is about to move, and D-02 forbids
  adding any delay to resolve it.
- **The lifted-card overhang:** a lifted card is drawn 72 wide but hit-tested 60, so a tap on its
  visible 12 px overhang selects the right-hand neighbour instead of sending. **Accepted** — widening
  the lifted hit rect would shrink that neighbour's strip to 40.8 physical px at the 0.85 scale
  floor, below the project's own 48 px floor.

**D-34 binds every line:** vanilla Roblox UI only — `Frame`, `TextLabel`, `ImageLabel`,
`TextButton`, `UICorner`, `UIStroke`, `UIGradient`, `TweenService` and plain Luau. If an executor
believes a library is required, that is a **BLOCKER** to raise with the owner.

Output: `CardFace.luau`, `CardHand.luau`, `CardPiles.luau`, and an extended discipline gate.
</objective>

```luau
--!strict  -- src/client/ui/CardFace.luau
export type Visual = "Idle" | "Selected" | "Arriving" | "InFlight" | "Returning" | "ForcedOut"
export type CardFace = {
	setFace: (self: CardFace, rank: number?, copy: number?) -> (),  -- nil, nil = face-down back
	setVisual: (self: CardFace, visual: Visual) -> (),
	moveToSlot: (self: CardFace, slot: Layout.Slot, animate: boolean) -> (),
	flyTo: (self: CardFace, target: Vector2, visual: Visual, onDone: (() -> ())?) -> (),
	flip: (self: CardFace) -> (),            -- width 1 -> 0 -> 1 over TWEEN.FLIP
	instance: (self: CardFace) -> Frame,
	destroy: (self: CardFace) -> (),
}
CardFace.new = function(parent: Frame, solution: Layout.Solution) -> CardFace
```

**Anatomy, every value from `Faces` and `Layout`:** corner index at `INDEX_INSET_X` / `INDEX_INSET_Y`
— rank glyph at `TEXT_SIZE.BODY` bold with the suit pip below it; the centre pip at
`TEXT_SIZE.HEADING`; the opposite corner repeated rotated 180 (**not on jokers**); a joker's star
plus `JK`, a double stroke, and the **rule band** whose text comes from
`Faces.JOKER_BAND[mode]`. **There is no `if mode == "Wild"` anywhere** (D-23): the band is read from
the table, because `CardPool.JOKER_MODE` is a live flag and the same card means two different things
depending on configuration.

**Pips:** `Faces.PIP_SOURCE` decides. `"glyph"` renders `pip.glyph` in a `TextLabel`; `"sprite"`
renders `pip.sprite` through `ImageLabel.ImageRectOffset` / `ImageRectSize`. **Do not build hearts or
spades from rotated Frames** (UI-SPEC "Don't Hand-Roll"); a diamond-from-Frame is acceptable only as
a clearly marked placeholder. The sprite asset is **M-16**, so with no asset id the sprite path must
render a visible, obviously-placeholder box rather than nothing — a silently invisible pip would read
as a bug in every later check.

**Colour is decorative** (D-24): `pip.isRedByDefault` picks `SUIT_RED` or `SUIT_BLACK` and **nothing
else reads it**. Identity is `(rankGlyph, silhouette)`.

```luau
export type Hand = {
	-- Called after every reducer transition. `display` is the authoritative picture and `changes`
	-- is what to animate; the renderer diffs nothing itself.

	setInputKind: (self: Hand, kind: Hints.InputKind) -> (),
	destroy: (self: Hand) -> (),
}

	tapSlot: (cardId: number?) -> (),
	tapOff: () -> (),
}) -> Hand
```

| Element | Implementation |
|---|---|
| hit strips | one invisible `TextButton` per slot from `Solution.slots[i].hit`: `BackgroundTransparency = 1`, `Text = ""`, `AutoButtonColor = false`, `Active = true`. Created once at `MAX_HAND = 5` and shown or hidden by hand size — **never recreated**, so a tap can never land on a button mid-destruction |
| hit strip position | **snaps** to `Solution.slots[i].hit` the instant the hand size changes (F7). Only the card visuals tween |
| hand 4 | the strips stay `Active = true` and their callback is still `tapSlot`, which the **reducer** makes inert (plan 04-09's F6 rule). They must remain `Active` so a tap does not fall through to the backdrop and clear a selection |
| backdrop | one `TextButton` over the whole root behind everything, `Active = true`, calling `tapOff` (D-04). Its `ZIndex` is below every slot |
| z-order | later slots above earlier ones; the selected card is raised to the top via `ZIndex`, never by reparenting |
| animation | `Change` kinds map one-to-one: `Added` with an id -> appear at slot; `Added` with no id -> face-down `Arriving` flying from the left pile over `TWEEN.DRAW`; `Flipped` -> `flip` over `TWEEN.FLIP`; `Returned` -> fly back from the right pile over `TWEEN.RETURN` with a `Back` overshoot; `Removed` -> leave like `InFlight` over `TWEEN.SEND` |
| the return is deliberately slower and bouncier than the send | 0.25 s `Quad Out` with overshoot against 0.18 s `Quad In`, **so it reads as a return rather than a teleport (D-11)**. A correction and a hard rejection are visually identical and carry no text, no sound and no colour flash (D-12) |
| a `Returning` card is tappable **immediately** | the hit strip is at the slot for the whole flight; the flight is cosmetic and gates nothing (D-02) |
| ordering | cards are laid out in **arrival order and never re-sorted by rank** — a re-sort on draw would move slots under a thumb |

```luau
export type Piles = {

	setRight: (self: Piles, count: number) -> (),
```

| Pile | Label | States, carried by **text and shape**, never colour alone |
|---|---|---|
| left (tappable) | `Draw` / `Locked` | **Drawable** (hand 4, count >= 1): `Draw`, full opacity, accent ring pulsing `STROKE.PULSE_MIN`..`PULSE_MAX` at `PULSE_HZ.DRAW_RING`. **Locked** (hand 5): `Locked`, art 60% transparent, **ring removed**, taps are no-ops. **Empty** (hand 4, count 0): `Draw`, dashed-outline empty slot with no art, numeral `0` |
| right (inert, D-06) | `Next` | always static art plus the exact count, with a drawn right-pointing triangle for direction. The count updates immediately on a predicted pass and reverts on correction |

**Both panels are `Active = true` no-op sinks.** Neither sends a game action; the left pile's tap
callback reaches the reducer (which makes it inert unless drawable) and the right pile's keeps the
selection and pulses the strip hint. **A tap on either must never reach the backdrop**, because the
backdrop clears the selection (D-04) and a fumbled tap must not deselect a card the player is about
to send.

**Counts are exact only for the local player** (CARD-13): the left count is my inbox depth and the
right count is the downstream seat's. Other seats get stack height on the 3D table and no numerals
(plan 04-19). **There is no dealer marker anywhere** — the dealer's left pile *is* the deck, so their
stack is the tallest object on the table by construction.

**The pile renderer is told nothing about the AFK state** (plan 04-16's resolution of the UI-SPEC's
"Minor" FLAG): at hand 4 the AFK cue pulses nothing, so the ring keeps its single meaning.
