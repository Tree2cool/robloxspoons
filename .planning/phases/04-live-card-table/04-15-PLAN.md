<objective>
Keep a seated seeker in their chair, server-side, and let them go the instant they complete a set.

Purpose, and the reason this is a security control rather than an animation: **no avatar seating or
stand-up code exists anywhere in the tree.** Phase 4 research grepped
`Humanoid|\.Sit|SeatPart|PivotTo|WalkSpeed` over `src/` and found only comments; the seats are plain
`Seat1..Seat9` Parts in the map contract. D-15 of `01-CONTEXT.md` (a finisher **stands up and runs**,
no teleport), D-30 (control returns **instantly**) and D-31 (the table sees the diegetic event) all
depend on code that does not exist yet.

**Client-side control hiding cannot be the thing that keeps a seeker at the table.** A cheat client
can re-enable its own controls and walk off to hunt before completing a set — which is a direct
gameplay exploit, because find order drives SCORE-01..03 and there are two fewer spoons than
players. So the hold is server-side and the client hiding (plan 04-11) is ergonomics. This plan is
the enforcement half of UX-02.

**The release is a scoring constraint.** D-30: the set slams down, the chair pushes back, and the
player is already running while the flourish plays around them. Any beat that holds the finisher
still is literally taking points off them, so the release happens in the `Completed` handler, before
the flourish starts.

**The mechanism is assumption A2 and is UNVERIFIED.** `04-RESEARCH.md` records it as such: "the
server-side avatar hold can be done with `Humanoid` speed/jump zeroing or an anchored root; the exact
mechanism is unverified... the plan must choose and Studio-verify. Wrong choice = avatar can slide or
physics jitters." This plan chooses, structures the choice so it is swappable behind one seam, and
routes the verification to **M-11**.

Output: `CardSeatHold.luau`, the Roblox effects in `CardService`, and the hold gate.
</objective>

```luau
--!strict  -- src/server/core/CardSeatHold.luau

export type Vec3 = { x: number, y: number, z: number }
export type Pose = { position: Vec3, look: Vec3 }

-- Every Roblox effect, injected. `pivotTo` returns false when the player has no character yet,
-- which is ordinary at round start: the pose is queued and applied on the next CharacterAdded.
export type Effects = {
	setMovementScriptable: (playerId: number, scriptable: boolean) -> (),
	freezeHumanoid: (playerId: number, frozen: boolean) -> (),
	pivotTo: (playerId: number, pose: Pose) -> boolean,
	onTelemetry: (name: string, data: { [string]: number }) -> (),
}

export type CardSeatHold = {
	hold: (self: CardSeatHold, playerId: number, pose: Pose) -> (),
	release: (self: CardSeatHold, playerId: number) -> (),
	-- The avatar respawned. If the player is still held, re-apply; otherwise do nothing.
	onCharacterAdded: (self: CardSeatHold, playerId: number) -> (),
	-- The player left. Drops the entry WITHOUT firing any effect: there is no avatar to restore and
	-- touching a departed Player is how a service leaks a reference.
	forget: (self: CardSeatHold, playerId: number) -> (),
	releaseAll: (self: CardSeatHold) -> (),
	isHeld: (self: CardSeatHold, playerId: number) -> boolean,
	heldCount: (self: CardSeatHold) -> number,
}
CardSeatHold.new = function(effects: Effects): CardSeatHold
```

**The transition table. The order inside each row is the contract and the spec asserts it.**

| Call | Effects, in exactly this order | Why this order |
|---|---|---|
| `hold(p, pose)` when not held | `setMovementScriptable(p, true)`, `freezeHumanoid(p, true)`, `pivotTo(p, pose)` | **Stop the avatar before placing it.** If the pose were applied first, the player could walk out of the chair in the window between the two calls, and on a laggy client that window is real |
| `hold(p, pose)` when already held | **nothing** | idempotent; a re-publish or a double seat must not re-pivot a seated player and yank them mid-animation |
| `release(p)` when held | `freezeHumanoid(p, false)`, `setMovementScriptable(p, false)` | **Restore the physical capability BEFORE handing control back**, so the finisher's very first input actually moves them. Reversed, the first frames of input would hit a zero-speed humanoid — a visible stutter on the one action a score depends on (D-30) |
| `release(p)` when not held | **nothing** | idempotent and safe to call twice; completion, bench and disconnect may all fire for the same player |
| `onCharacterAdded(p)` when held | `freezeHumanoid(p, true)`, `pivotTo(p, queuedPose)` | A respawn hands back a fresh `Humanoid` with default speed, so the freeze must be re-applied. `setMovementScriptable` is a `Player` property and survives a respawn, so it is **not** re-set — and a comment must say that, or someone will add a redundant call |
| `forget(p)` | **nothing** | no effect on a departed player |
| `releaseAll()` | `release` for every held player, in ascending `playerId` | deterministic for the round-end path |

**`pivotTo` returning false:** record the pose as pending and emit
`onTelemetry("seat_hold_deferred", { playerId = p })`. The freeze and the movement mode are still
applied, so a player whose character loads late is already restricted when it arrives.

**The Roblox effects, in `CardService.luau`'s marked block.** The mechanism is **assumption A2,
unverified**, and these are the choices:

| Effect | Implementation | Restore |
|---|---|---|
| `setMovementScriptable(p, true)` | `player.DevComputerMovementMode = Enum.DevComputerMovementMode.Scriptable` and `player.DevTouchMovementMode = Enum.DevTouchMovementMode.Scriptable`. **Server only** — the docs state these cannot be set from a LocalScript | back to the values captured from `StarterPlayer.DevComputerMovementMode` / `DevTouchMovementMode` **at boot**, not to a hard-coded `UserChoice`: the place's own default is the correct restore target and capturing it means a later Studio change is honoured |
| `freezeHumanoid(p, true)` | `humanoid.WalkSpeed = 0`; `humanoid.JumpHeight = 0` **and** `humanoid.JumpPower = 0` (which applies depends on `UseJumpPower`, so set both and let the unused one be inert) | back to the values captured from `StarterPlayer.CharacterWalkSpeed`, `CharacterJumpHeight` and `CharacterJumpPower` at boot |
| `pivotTo(p, pose)` | `character:PivotTo(CFrame.lookAt(position, position + look))`; return `false` when `player.Character` or its `PrimaryPart` is `nil` | nothing to restore |

**Rejected and why, recorded so M-11 has a fallback list rather than a blank page:**
anchoring the `HumanoidRootPart` (it fights the physics solver and the research warns of jitter and
sliding); `Humanoid.Sit` with a real `SeatPart` (the seats are plain Parts in the map contract and
converting them is a map-contract change, which is Phase 3's territory and out of this phase's
boundary); `humanoid:ChangeState(Enum.HumanoidStateType.Physics)` (undocumented behaviour under the
IAS migration, and this phase has already been burned once by an undocumented input API).
**If zeroing proves insufficient in M-11, the recorded next attempt is `Sit` on a converted seat,
and that is a Phase 6 map-contract change, not a hot fix.**
