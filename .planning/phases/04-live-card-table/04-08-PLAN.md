<objective>
Turn the whole UI-SPEC geometry into pure arithmetic, so UX-01's 48 px floor and UX-03's safe area
become unit assertions instead of a reviewer squinting at a Studio emulator.

Purpose: this is the only way those two requirements get a machine gate at all. The UI-SPEC's own
acceptance tests 1 and 2 are fully covered here, and the arithmetic half of test 3.

**It also resolves checker FLAG F4, which the UI-SPEC handed to the planner and which phase research
made worse.** The strip's self-imposed 450 design px limit was already about 6 px short of its own
two 38-character strings at **default** text size (bold glyphs average nearer 12 px than 11), and
`GuiService.PreferredTextSize = Largest` scales text **even when `TextScaled = false`**. The
resolution applies both halves of the UI-SPEC's "widen the strip, or cap the strings" and adds D-36's
constraint on top:

1. the strip spans the **full safe width** minus an 8-unit margin each side (>= 634 design px at
   every supported viewport, against the old 450);
2. every strip string is capped at **34 characters** (`Config.Card.STRIP_MAX_CHARS`), giving
   `634 / (34 * 12) = 1.55x` of headroom before overflow;
3. plan 04-16 puts a `UITextSizeConstraint` on the strip label so the text cannot grow past that.

The four UI-SPEC strings that exceed 34 characters are **rewritten, not truncated**, in plan 04-11 —
D-36 records that truncating the clause which says what is about to happen is worse than no message.

Output: `Layout.luau` and the UX-01 / UX-03 gate.
</objective>

```luau
--!strict
local Card = require("../Config/Card")

-- Plain data. PHYSICAL pixels, measured from the top-left of the FULLSCREEN area (V-24: insets are
-- relative to the rect covering all visible pixels).
export type Rect = { x: number, y: number, w: number, h: number }
export type Insets = { top: number, bottom: number, left: number, right: number }
export type Viewport = { width: number, height: number, insets: Insets }

-- A STRING, not an Enum: this is a pure zone. Plan 04-16 maps it to Enum.ScreenInsets.
-- V-24 VERIFIED 2026-11-05 against primary docs: CoreUISafeInsets = DeviceSafeInsets plus Roblox
-- core UI, and the docs explicitly recommend it "for any ScreenGui that contains interactive
-- and/or important UI elements such as buttons and status messages". That is exactly the hand, the
-- tappable left pile, the AFK countdown and every status cue.
Layout.SCREEN_INSETS = "CoreUISafeInsets"

-- Every number in the UI-SPEC, in one frozen table, in DESIGN units. Passed as an argument to
-- `solve` and `problems` so a mutation is an injected broken dependency, never a source edit.
export type Design = {
	REF_W: number, REF_H: number, SCALE_MIN: number, SCALE_MAX: number,
	HANDZONE_H: number, STRIP_H: number, STRIP_TEXT_H: number, DRAIN_H: number, STRIP_MARGIN: number,
	CARD_W: number, CARD_H: number, STEP: number, LIFT: number,
	INDEX_INSET_X: number, INDEX_INSET_Y: number,
	HIT_W: number, HIT_LAST_W: number, HIT_H: number,
	PILE_W: number, PILE_H: number, PILE_ART_W: number, PILE_ART_H: number, PILE_MARGIN: number,
	FAN_BOTTOM_MARGIN: number, MIN_FAN_PILE_GAP: number,
	CALLOUT_H: number, CALLOUT_GAP: number,
	TOUCH_FLOOR_PHYSICAL: number, TABLE_REGION_MIN_FRACTION: number,
	TABLE_REGION_HEIGHT_GUARANTEE: number, TABLE_PROJECTION_MARGIN: number,
	CHAR_WIDTH_PROXY: number,
}
Layout.DESIGN: Design = {
	REF_W = 760, REF_H = 350, SCALE_MIN = 0.85, SCALE_MAX = 1.5,
	HANDZONE_H = 144, STRIP_H = 28, STRIP_TEXT_H = 24, DRAIN_H = 4, STRIP_MARGIN = 8,
	CARD_W = 72, CARD_H = 92, STEP = 60, LIFT = 16,
	INDEX_INSET_X = 16, INDEX_INSET_Y = 4,          -- 16, not 12: checker FLAG F2
	HIT_W = 60, HIT_LAST_W = 72, HIT_H = 108,       -- 108 = CARD_H 92 + LIFT 16: checker FLAG F1
	PILE_W = 84, PILE_H = 96, PILE_ART_W = 52, PILE_ART_H = 68, PILE_MARGIN = 8,
	FAN_BOTTOM_MARGIN = 4, MIN_FAN_PILE_GAP = 24,
	CALLOUT_H = 32, CALLOUT_GAP = 4,
	TOUCH_FLOOR_PHYSICAL = 48, TABLE_REGION_MIN_FRACTION = 0.58,
	TABLE_REGION_HEIGHT_GUARANTEE = 300, TABLE_PROJECTION_MARGIN = 8,
	CHAR_WIDTH_PROXY = 12,                          -- bold 20 average; F4's 11 was optimistic
}  -- frozen

Layout.OVERLAP = function(d: Design): number  -- CARD_W - STEP = 12, derived, never a second constant

export type Slot = { index: number, hit: Rect, card: Rect, lifted: Rect }
export type Named = { name: string, rect: Rect, interactive: boolean }
export type Solution = {
	scale: number,
	safe: Rect,          -- the inset rect, in physical px
	designW: number,     -- safe.w / scale
	designH: number,
	tableRegion: Rect,
	tableRegionFraction: number,  -- ALWAYS reported, so a failing device is observed not guessed
	handZone: Rect,
	strip: Rect,
	drain: Rect,
	leftPile: Rect,
	rightPile: Rect,
	fan: Rect,
	slots: { Slot },
	calloutStack: { Rect },  -- Card.MAX_CALLOUTS entries, top centre of tableRegion
	elements: { Named },     -- every rect with its name and whether it takes input
}

Layout.scaleFor = function(safeWidth: number, safeHeight: number, d: Design?): number
	-- clamp(min(safeWidth / REF_W, safeHeight / REF_H), SCALE_MIN, SCALE_MAX)
Layout.solve = function(viewport: Viewport, handSize: number, d: Design?): Solution
Layout.problems = function(viewport: Viewport, handSize: number, d: Design?): ({ string }, number)
	-- returns the problems and the number of checks actually performed
```

**Geometry, derived in `solve` and never duplicated anywhere else:**

| Element | Rule (design units inside the safe rect; multiply by `scale` for physical) |
|---|---|
| `handZone` | bottom `HANDZONE_H` of the safe rect |
| `tableRegion` | the rest of the safe rect, above it; `tableRegionFraction = tableRegion.h / safe.h` |
| `strip` | handZone top, inset `STRIP_MARGIN` each side, height `STRIP_H`. **Spans the full safe width (F4 resolution).** |
| `drain` | the bottom `DRAIN_H` of `strip`, full strip width |
| `leftPile` | handZone, `PILE_MARGIN` from the safe left edge, `PILE_MARGIN` from the bottom, `PILE_W x PILE_H` |
| `rightPile` | mirrored on the right |
| `fan` | width `CARD_W + (handSize - 1) * STEP`, **centred on the safe rect**, bottom `FAN_BOTTOM_MARGIN` above the handZone bottom, height `CARD_H` |
| slot `i` card | `fan.x + (i - 1) * STEP`, width `CARD_W`, at the fan's y |
| slot `i` lifted | the same rect raised `LIFT` |
| slot `i` hit | width `HIT_W` (`HIT_LAST_W` for `i == handSize`), height `HIT_H`, bottom-aligned with the card, left-aligned with the card. **Independent of z-order and of whether the card is lifted (F7).** |
| `calloutStack[k]` | `CALLOUT_H` tall, centred horizontally on `tableRegion`, stacked downward from its top with `CALLOUT_GAP` |

`elements` lists: `slot1..slotN` (interactive), `leftPile` (interactive), `rightPile`
(**interactive**: it is an `Active` no-op sink by D-06, so it must still meet the floor and sit
inside the safe rect), `strip`, `drain`, `calloutStack[k]` (all non-interactive).

**`problems` must report, each with its own distinguishing prefix:**

| Problem | Message prefix |
|---|---|
| an interactive rect narrower or shorter than `TOUCH_FLOOR_PHYSICAL` **physical** px | `below touch floor:` |
| any rect not fully inside the safe rect | `outside safe rect:` |
| `tableRegionFraction < TABLE_REGION_MIN_FRACTION` while `safe.h >= TABLE_REGION_HEIGHT_GUARANTEE` | `table region too small:` |
| `safe.h < TABLE_REGION_HEIGHT_GUARANTEE` | `height below guarantee:` — **reported, never used to loosen the bound.** The UI-SPEC is explicit: if a real device falls below 300 physical px of safe height, the planner reports it |
| a lifted slot rect intersecting `strip` | `lift overlaps strip:` |
| clear gap between `fan` and either pile `< MIN_FAN_PILE_GAP` | `fan pile gap:` |
| `fan` intersecting either pile, or `strip` intersecting either pile | `overlap:` |
| `INDEX_INSET_X <= OVERLAP(d)` | `index inset:` (F2: at 12 the outline spilled onto the neighbour's glyph) |
| `STEP * SCALE_MIN < TOUCH_FLOOR_PHYSICAL` | `step below touch floor:` (the 0.85-floor derivation) |
| `strip.w < STRIP_MAX_CHARS * CHAR_WIDTH_PROXY * scale` | `strip too narrow:` (F4) |
| `HIT_H ~= CARD_H + LIFT` | `hit height:` (F1) |
