<objective>
The thin Roblox adapter and the boot wiring that make the card table actually run: the one
conversion site, the two clocks, the 10 Hz sweep, the `EngineConfig` values, and a deliberately dumb
`RoundStub` so Phase 4 runs end to end with Phases 5 and 6 absent.

Purpose: everything behavioural already exists in pure cores with its own tests. This plan's job is
to keep the Roblox layer to `require`, property assignment, a `Heartbeat` accumulator and remote
wiring — because, as the research puts it, *every place this phase is tempted to add logic to the
Roblox-touching layer is a place a test can no longer reach it.*

Two things in here are load-bearing beyond wiring:

- **CLAUDE.md rule 5, the unit boundary.** The simulator's clock is float seconds and the shipped
  clock is integer deciseconds. The conversion `AUTO_PASS_DECI = floor(8.0 * 10 + 1e-9) = 80` is
  written **once**, here, with the ceiling assert beside it. `tests/card/deci_lock.spec.luau` is the
  drift test, following the `Gateway.PHASES` / `Manifest.PHASES` precedent.
- **The CARD-14 resync push.** A gateway-level rejection never reaches the card core, so the
  client's `seq` is never acked. Wiring `onReject` to `CardTable:onGatewayReject` is the **primary**
  mechanism that stops a rate-limited tap leaving a card visibly gone forever — the exact "visible
  glitch" success criterion 2 forbids. Plan 04-09's age watchdog is only the backstop.

Output: `CardService.luau`, the wired `Main.server.luau`, and the deci drift test.
</objective>

--   * os.clock()          the scheduling clock. Floored to integer deciseconds and handed to the
--                         pure cores as `nowDeci`. Monotonic within a server, meaningless across.

-- a relative require would resolve on disk and fail in Studio (guard rule R6).
local CardConfig = require(ReplicatedStorage.Shared.Config.Card)
local CardPool = require(ReplicatedStorage.Shared.Config.CardPool)

-- THE ONE CALL SITE OF THE CONVERSION (CLAUDE.md rule 5). The ARITHMETIC lives in the pure
-- src/server/core/CardTiming.luau, for one reason: this file names game:GetService, so Lune cannot
-- load it, and an inline expression here would be testable by nothing. A spec could only recompute
-- the formula (then the two drift without either failing) or grep its text (then a COMMENT
-- satisfies the grep while the code does something else -- the defect class that bit this project
-- four times in Phase 3). So: arithmetic there, single call here.
-- D-13: 8.0 s is the ceiling itself and the owner chose to sit exactly at it, BECAUSE V-35 (whether
-- the bot reaction-time model represents humans) is open. Do not describe it as validated.
-- Honest consequence (assumption A5): flooring a continuous clock and sweeping at 10 Hz realises
-- (7.9, 8.1] of wall time against CARD-16's "must not exceed 8.0 s", so the overshoot is up to
-- 0.1 s. The deviation is ONE-SIDED: an arming at real time c stores floor(10c) + D, so the
-- deadline is first observable at elapsed (D - frac(10c))/10, which for D = 80 is in (7.9, 8.0] --
-- flooring only ever shortens -- and the 10 Hz sweep adds up to +0.1 s. Verified over 100,000
-- fractional phases: [7.900, 8.000] before sweep lateness, 8.100 after. (Research assumption A5
-- says "+-0.1 s on arming"; that is wrong, read it as "-0.1 s".)
-- The ceiling binds the CONFIGURED value, which is exactly 8.0 s. Plan 04-20 puts the gap to the
-- owner explicitly; passing 7.9 here instead would make the realised maximum 8.000 s and close it.
-- Do not make that change without the owner's decision.
local AUTO_PASS_DECI = CardTiming.autoPassDeci(CardPool.AUTO_PASS_MAX_SECONDS, Round.DECISECONDS_PER_SECOND)
assert(AUTO_PASS_DECI <= CardPool.AUTO_PASS_MAX_SECONDS * Round.DECISECONDS_PER_SECOND, "AUTO_PASS_DECI exceeds the locked ceiling")

-- THIS FILE BUILDS THE TWO PURE CORES AND HANDS THEM TO CardTable AS OBJECTS (plan 04-12's `Deps`
-- takes `idle` and `stall`, not loose numbers). `AUTO_PASS_DECI` therefore reaches the game through
-- exactly one path: this constant -> IdleClock.new -> CardTable. `deci_lock` case 1 asserts over
-- comment-stripped source that the constant assigned above is the one passed here, which is what
-- makes the chain shipped rather than merely composed in a spec.
local function buildCores()
	local idle = IdleClock.new({
		autoPassDeci = AUTO_PASS_DECI,
		maxStrikes = CardConfig.MAX_STRIKES,
	})
	local stall = StallDetector.new({
		actionsPerSeat = CardConfig.STALL_ACTIONS_PER_SEAT,
		minDeci = CardConfig.STALL_MIN_SECONDS * Round.DECISECONDS_PER_SECOND,
		cueDeci = CardConfig.STALL_CUE_SECONDS * Round.DECISECONDS_PER_SECOND,
		repeatDeci = CardConfig.STALL_REPEAT_SECONDS * Round.DECISECONDS_PER_SECOND,
		onTelemetry = deps.onTelemetry,
	})
	return idle, stall
end

-- NOTE on what is NOT here: `IdleClock` and `StallDetector` are not `CardService` dependencies,
-- they are things `CardService` BUILDS (see `buildCores` above) and injects into `CardTable`. The
-- adapter is the only place that holds both the config values and the constructors.
export type Deps = {
	publisher: any,           -- the Publisher from NetServer.start
	setPhase: (phase: string) -> (),

	onTelemetry: (name: string, data: { [string]: number }) -> (),

}

	onGatewayReject: (self: CardService, userId: number, intentName: unknown, code: string) -> (),
	seatedUserIds: (self: CardService) -> { number },
	destroy: (self: CardService) -> (),

CardService.new = function(deps: Deps): CardService

**The 10 Hz sweep:** one `RunService.Heartbeat` connection with a float accumulator. When the
accumulator passes `1 / CardConfig.SWEEP_HZ`, subtract the interval (do not reset to zero, or the
sweep drifts) and call `cardTable:tick()` once. **No per-seat `task.delay` timers, ever** — the pure
tick returns commands and the core applies them.

**The Rng seed (ASVS V6).** `Rng.luau`'s header documents that xorshift32 seeded with a small
integer produces a *constant* first output, and the simulator seeds with small sequential counters.
A round's deal must not be guessable, so seed from a mixed, non-sequential source:
`bit32.bxor(math.floor(os.clock() * 1e6) % 2147483647, DateTime.now().UnixTimestampMillis % 2147483647)`,
with a comment naming the header's warning. **Never a round counter.**
