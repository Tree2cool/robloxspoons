`tests/harness/RecordingPublisher.luau`:

```luau
--!strict
export type Call = {
	method: "toPlayer" | "toSeated" | "toAll",
	userId: number?, -- nil for toSeated / toAll
	kind: string,
	payload: any,
}

-- `leak` is the INJECTED DEFECT (the FakeScheduler.cancelIsNoop idiom): with it set, every call
-- made through `toPlayer` is recorded as a `toAll` broadcast instead. It models a real regression
-- -- a later edit routing a private kind through the public method -- so a privacy gate that
-- cannot see it is proven unable to fire.
export type Options = { leak: boolean? }

export type RecordingPublisher = {
	-- exactly the Publisher shape that src/server/core/CardRouting.luau exports
	toPlayer: (userId: number, kind: string, payload: unknown) -> (),
	toSeated: (kind: string, payload: unknown) -> (),
	toAll: (kind: string, payload: unknown) -> (),
	-- inspection
	calls: () -> { Call },
	callsTo: (userId: number) -> { Call },          -- toPlayer calls for that userId PLUS every broadcast
	callsOfKind: (kind: string) -> { Call },
	reset: () -> (),
}

local function new(options: Options?): RecordingPublisher
```

`callsTo(userId)` must include broadcasts, because "what did this player see" is the question every
CARD-13 assertion asks, and a broadcast is seen by everyone. A fake that answered only `toPlayer`
calls would make the leak invisible, which is the exact defect class this file exists to catch.

`src/server/core/CardTiming.luau` — **the one seconds-to-deciseconds conversion, as a pure
function**:

```luau
--!strict
-- PURE ZONE: no Roblox API, no clock read, no requires. Arithmetic over two numbers.
--
-- WHY THIS IS A FUNCTION AND NOT AN EXPRESSION IN THE ADAPTER. CLAUDE.md rule 5 wants exactly one
-- conversion site, and `src/server/services/CardService.luau` is the right place to CALL it --
-- that is where the config values are read by absolute DataModel path (guard R6). But `CardService`
-- names `game:GetService`, so Lune cannot load it, which means an expression written inline there
-- is testable by nothing: a spec can only recompute the formula (and then the two can drift without
-- either failing) or grep for its text (and then a COMMENT satisfies the grep while the code does
-- something else -- the defect class that bit this project four times in Phase 3).
--
-- So the arithmetic lives here, where a spec can drive it, and the adapter remains the single
-- CALLER. One site, and a reachable gate. tests/card/config_lock.spec.luau drives this function
-- directly; tests/card/cardtable.spec.luau proves its result reaches IdleClock.
--
-- THE EPSILON AND THE FLOOR ARE BOTH LOAD-BEARING. `0.7 * 10` is 7.000000000000001 in IEEE double,
-- so a ceil or a round would produce 8 and exceed a ceiling the owner locked. Floor-with-epsilon
-- can never exceed `seconds * perSecond`, which is what D-13 requires of the CONFIGURED value.
local function autoPassDeci(maxSeconds: number, decisPerSecond: number): number
	-- errors by name on a non-finite or non-positive input: a NaN deadline can never be reached, so
	-- the AFK clock would silently never fire (NaN fails every comparison)
	...
	return math.floor(maxSeconds * decisPerSecond + 1e-9)
end

return { autoPassDeci = autoPassDeci }
```

**`CardService` must contain exactly one call to it and no arithmetic of its own** (plan 04-14
asserts that over comment-stripped source). The function is deliberately general — it takes the two
numbers rather than reading config — so it stays in the pure zone and so the spec can drive it over
inputs the shipped config never produces.
