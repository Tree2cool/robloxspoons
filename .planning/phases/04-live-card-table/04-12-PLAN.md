<objective>
The pure server card core: the thing that turns a client intent into an `Engine.apply` call and
turns the returned events into exactly the right message to exactly the right audience.

Purpose: this is where CARD-13 is either true or false. Guard R4 confines
`FireClient`/`FireAllClients` to `NetServer.luau`, and plan 04-05 made the audience a frozen table,
so *"is any private data broadcast?"* reduces to *"which `Publisher` method does this file call?"* —
and that is now answerable by a unit test with a recording fake. A client must never receive another
seat's hand contents **in any form**; this is the card-table analogue of CLAUDE.md rule 3 and the
same cheat-client reasoning applies.

It is also where the engine boundary is respected or violated. `Engine.newRound` and `Engine.apply`
are the **entire** public surface. The engine is pure, synchronous, fuzz-proven and gate-passed; the
shell adapts to it and reimplements no rule. `apply` returns its events precisely so that nothing is
published inside a mutation (CLAUDE.md rule 6) — a yield mid-mutation would let two handlers
interleave.

Output: `CardTable.luau`, the CARD-13 privacy gate, and a scripted-bot integration test that proves
driving the engine through this shell reaches the same state as driving it directly.
</objective>

```luau
--!strict
local Engine = require("../engine/Engine")
local Pool = require("../engine/Pool")
local Types = require("../engine/Types")
local CardRouting = require("./CardRouting")
local IdleClock = require("./IdleClock")
local StallDetector = require("./StallDetector")

-- The shell's OWN removal cause. Narrowed on purpose: Engine.apply throws on "Completed", which it
-- owns. A type error here is cheaper than a thrown round.
export type ShellRemoveCause = "Disconnected" | "Benched"

export type Vec3 = { x: number, y: number, z: number }
-- EXACTLY these four fields and no others. Plan 04-14's CardService builds one of these per seat
-- from `mapSpec.cardTable.seats`; it must construct the struct field by field and must NEVER pass a
-- map node or a table it did not build. The RoundStart key-set assertion in cardtable.spec is what
-- enforces that, and its mutation injects an extra key to prove the assertion fires.
export type SeatSpec = { playerId: Types.PlayerId, position: Vec3, look: Vec3 }

export type Deps = {
	publisher: CardRouting.Publisher,
	nowDeci: () -> number,
	rng: any,                       -- an Rng from src/server/engine/Rng.luau; seeded by the adapter
	-- Values, never config modules (guard R6). The adapter reads CardPool / Config.Card.
	extraRanks: number,             -- CardPool.EXTRA_RANKS
	jokers: number,                 -- CardPool.JOKERS
	jokerMode: Types.JokerMode,     -- CardPool.JOKER_MODE
	autoPassDeci: number,           -- 80
	maxStrikes: number,             -- 3
	stall: { actionsPerSeat: number, minDeci: number, cueDeci: number, repeatDeci: number },
	-- Two-clock rule (RoundDriver.luau:9-11): the core never reads a wall clock and never feeds a
	-- published value back. The adapter turns a remaining-deci count into a Unix deadline with
	-- GetServerTimeNow; it is DISPLAY ONLY (D-16).
	unixDeadlineFor: (remainingDeci: number) -> number,
	-- Phase 5 owns the hunt. Phase 4's implementation logs, releases the avatar and restores
	-- controls, so the phase runs end to end without Phase 5 existing.
	onCompleted: (seat: Types.SeatId, playerId: Types.PlayerId, rank: Types.Rank) -> (),
	onSeatRemoved: (seat: Types.SeatId, playerId: Types.PlayerId, cause: Types.RemoveCause) -> (),
	onTelemetry: (name: string, data: { [string]: number }) -> (),
}

export type CardTable = {
	-- `seats` is ALREADY IN SEAT ORDER: index 1 is the dealer (CARD-05, SeatOrder is Phase 6's job).
	-- Builds the round, assigns copies once, publishes RoundStart to the seated and one private Sync
	-- per seat.
	--
	-- WHY THE POSE IS AN ARGUMENT AND NOT A LOOKUP: the RoundStart payload has to carry each seat's
	-- pose (the client cannot read one from the replicated tree -- see the decision block below), and
	-- a pure core cannot read the map. Taking a NARROW four-field struct per seat is what makes the
	-- narrowness structural: there is no map node in scope to copy by accident, so nothing else from
	-- the map's Data folder can ride along into a published payload.
	start: (self: CardTable, seats: { SeatSpec }) -> (),
	-- The gateway's dispatch target. `payload` is the CLEAN copy Gateway produced.
	onIntent: (self: CardTable, userId: number, intentName: string, payload: unknown) -> (),
	-- A gateway-level rejection never reached this file, so the client's seq was never acked.
	-- Pushes that player a Sync at the current ackSeq (plan 04-09's primary resync mechanism).
	onGatewayReject: (self: CardTable, userId: number, intentName: unknown, code: string) -> (),
	-- The 10 Hz sweep. Drains IdleClock and StallDetector commands, applies each OUTSIDE any other
	-- apply, then publishes (rule 6).
	tick: (self: CardTable) -> (),
	-- A leaver. Routes through the ONE generic removal with cause "Disconnected" (rule 8).
	removePlayer: (self: CardTable, userId: number) -> (),
	seatOf: (self: CardTable, userId: number) -> Types.SeatId?,
	isLive: (self: CardTable) -> boolean,
	-- Test seam only: the engine state, so cardtable.spec can hash it. Never called in production
	-- and never published.
	debugState: (self: CardTable) -> Types.State,
}
CardTable.new = function(deps: Deps): CardTable
```

**`onIntent`, step by step. The order is the contract.**

1. `seat = roster[userId]`. **Never read a seat from the payload (rule 7).** No seat -> publish a
   `Sync` to that player (so a stray tap still resolves their pending queue) and stop.
2. Build the engine intent: `Draw{seat}` or `Pass{seat, cardId}` from `payload.cardId`.
3. `local result = Engine.apply(state, intent)` — synchronous, nothing else between.
4. **After it returns:** `idle:sync(viewOf(state), nowDeci, if result.ok then seat else nil)`;
   `stall:noteApply(state.liveCount, nowDeci)` when `result.ok`, and `stall:noteProgress(nowDeci)`
   when the batch contains a `Completed` or a `SeatRemoved`.
5. `local public, notices = CardRouting.split(result.events, copyOf)`.
6. Publish, in this order: the actor's `Sync` (**always**, with `ackSeq = payload.seq`, accepted or
   rejected — same message shape, which is D-12 holding at the wire level); then one `Notice` per
   private notice via `toPlayer`; then the `Table` batch via `toSeated` when `public` is non-empty;
   then a fresh `Sync` to every **other** seat whose hand, inbox or downstream depth changed.
7. Fire `onCompleted` / `onSeatRemoved` for each matching event, **after** publishing, so a sink that
   throws cannot swallow a message a client is waiting for.

**`result.reject` is never published.** It goes to `onTelemetry` only. D-12: a legitimate player
should never see one, and a message would hand a prober the name of the guard they tripped.

**`tick`, step by step.** `nowDeci` once, reused for the whole sweep so the sweep is a single instant.
Then drain `idle:tick(nowDeci)` in order:

| Command | Action |
|---|---|
| `AutoPass{seat}` | `IdleClock.pickUniform(state.seats[seat].hand, rng)`, then the same `apply` -> `split` -> publish path as `onIntent` with `playerActedSeat = nil` (an auto-pass is not a real action, so it must not reset strikes) |
| `Strike{seat, strikes, owes}` | `Notice{code="Strike", strikes, owes, cardId?}` to that seat's player via `toPlayer`; `cardId` is set only when an `AutoPass` for the same seat immediately preceded it |
| `Bench{seat}` | `Engine.apply(state, {kind="Remove", seat=seat, cause="Benched"})`, publish the batch, `Notice{code="Benched"}` to the player, `onSeatRemoved(...)` |

Then `deps.stall:tick(nowDeci)`: a `StallCue` yields a `Stall{active=true, showSeconds}` payload for
the seated and a `StallClear` yields `Stall{active=false}`.

**THE SWEEP APPLIES AND BOOKKEEPS EVERYTHING FIRST, THEN PUBLISHES. This is a change from the first
draft of this plan and it is load-bearing twice over.** The first draft said each command was "a
complete `apply` -> `split` -> publish cycle", which meant the real `tick` published the `AutoPass`
batch *before* issuing the `Bench` that followed it in the same sweep — and task 3's rule-6 mutant
was specified as exactly that behaviour, so the real code and the mutant were the same code. One of
them had to be wrong. The sweep now works like this:

1. drain `deps.idle:tick(nowDeci)` and `deps.stall:tick(nowDeci)` into one ordered command list;
2. for each command in order: `Engine.apply` (or the notice-only path), then `viewOf` +
   `deps.idle:sync` + `deps.stall:noteApply`/`noteProgress`, then `CardRouting.split`, and
   **append** the resulting payloads to a pending-publish list. **Nothing is published yet.**
3. after the whole list is processed, publish the collected payloads in order.

Rule 6 asks that events be returned and published after the mutation; doing it at **sweep**
granularity rather than per command satisfies that strictly, and it is what makes "every state
update is complete before the first publish" true of a whole sweep and not merely of one command.

**Each command's step 2 is individually contained** in the `xpcall` form from
`Gateway.luau:87-98`. This is where the `pcall` goes, and it is specified here because task 3
case 4b depends on it: one malformed or throwing command must not abort the rest of the sweep.
A contained failure goes to `onTelemetry` and the sweep continues with the next command.
**If a command throws, the payloads already collected are still published** in step 3 — a dropped
batch would leave every client's pending queue unresolved, which is worse than the failure itself.
Say so in a comment.

**`apply` is still never nested inside another `apply`,** and no publish ever happens with an
`apply` on the stack.

**`Sync` payload** (`toPlayer` only, ever):
`{ ackSeq, seat, hand = { FaceRecord }, inbox, downstream, idleDeadlineUnix? }`. `hand` is in
arrival order, taken straight from `state.seats[seat].hand` with `copyOf` applied. `inbox` is
`#state.seats[seat].inbox`; `downstream` is `#state.seats[state.seats[seat].next].inbox`.
`idleDeadlineUnix` is present **only** when `idle:deadlineDeci(seat)` is armed, computed via
`unixDeadlineFor` (D-16).

**`RoundStart` payload** (`toSeated`): `{ seats, jokerMode, ranks }` where each entry is
`{ seat, playerId, position = {x,y,z}, look = {x,y,z} }`.

> **Decision and its justification, because this is a new network exposure.** The 3D seat stacks
> (D-19, D-26) and the travelling cards must be drawn at the seat anchors, and the map contract puts
> `CardTable/Seats/Seat1..Seat9` under the map's **`Data`** folder, which is **never cloned into
> Workspace** (`MapContract.luau:5-17`). So a client has no way to learn a seat pose from the
> replicated tree, and it needs one. Seat poses are published here, deliberately and narrowly.
> **Why this is not a rule 3 violation:** rule 3 protects spoon positions, hands, piles and the
> default-spot pool. A seat pose is public by construction — an avatar is visibly sitting there, the
> camera is locked to the table, and `SpoonDefaultSpot`, `DecoyAnchor`, `SeekerSpawn` and
> `HiderSpawn` remain in `secretNames` and are not touched. **The narrowness is enforced:** the
> adapter passes the core a list of four-field structs, so there is no map node to copy by accident
> and nothing else from `Data` can ride along. A spec asserts the published payload's key set
> exactly.

**`viewOf(state)`** projects `{ live, handSize, inboxSize }` per seat for `IdleClock`. It must be
rebuilt from the state after every apply, for **every** seat — not only the actor — because a pass
changes the receiving seat's inbox and a removal changes the successor's.
