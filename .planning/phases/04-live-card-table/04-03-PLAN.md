Add the phase's entire client-to-server surface: two manifest intents and their rate limits, with
the rule-7 guarantee asserted as a structural property of the schema.

Purpose: CLAUDE.md rule 7 — *the client never names a pass target or a hand index.* `exactKeys`
already rejects any key not in the schema as `UnknownKey`, so writing the schema as exactly
`{ seq }` and `{ seq, cardId }` makes rule 7 **structural** rather than a check somebody has to
remember to write. The spec turns that from a property of the implementation into an asserted one,
naming each forbidden key explicitly, because "the schema happens to be tight" and "a test fails if
it loosens" are different guarantees.

This is the phase's narrowest plan and it has no dependencies, so it runs in wave 1 beside the
scaffolding.

Output: `Draw` and `Pass` in the manifest, their buckets, and the forbidden-key gate.

`src/shared/Net/Manifest.luau` — the two new entries, inside the existing `intents` table:

```luau
	-- CARD-02 / CARD-14. Both are Round-only: a card intent outside the round is dropped by the
	-- gateway's phase gate before it costs a lookup or a token.
	--
	-- RULE 7 IS STRUCTURAL HERE, not a handler check. `exactKeys` rejects any key outside the
	-- schema as `UnknownKey`, so there is no `seat`, no `to`, no `target` and no `index` a client
	-- could send. The server resolves the actor's seat from the Player the platform hands it, and
	-- `Ring.pass` resolves `next` inside `Engine.apply`. tests/net/manifest.spec.luau asserts each
	-- of those four names is rejected, for both intents.
	--
	-- `seq` is a client-chosen CORRELATION COUNTER, not a clock and not an index (rule 5). The
	-- server echoes it back as `ackSeq` so the client's pending queue can be resolved cumulatively.
	Draw = {
		phases = { "Round" } :: { RoundPhase },
		validate = Validate.exactKeys({ seq = Validate.integer({ min = 0, max = 2 ^ 31 }) }),
	},
	-- `cardId` is a STABLE CARD ID, which is a shuffled deck position carrying no rank information
	-- (engine Types.luau guarantee 2). The 64 bound is a SANITY CAP, not a game rule: the largest
	-- shipped pool is 4 * 12 + 1 = 49 cards. The rule is the engine's `UnknownCard` / `NotYourCard`,
	-- which this bound must never be mistaken for.
	Pass = {
		phases = { "Round" } :: { RoundPhase },
		validate = Validate.exactKeys({
			seq = Validate.integer({ min = 0, max = 2 ^ 31 }),
			cardId = Validate.integer({ min = 1, max = 64 }),
		}),
	},
```

1. Add a table-driven helper beside `phaseProblems`:
```luau
-- Rule 7, written once as data. `base` is a COMPLETE valid payload, so each case adds exactly one
-- defect: exactKeys reports MissingKey before UnknownKey, and a case that omitted a required key
-- while adding a forbidden one would assert the wrong code and prove nothing about rule 7.
local FORBIDDEN_KEYS = { "seat", "to", "target", "index", "hand", "slot", "userId" }
local BASES: { [string]: { [string]: any } } = {
	Draw = { seq = 1 },
	Pass = { seq = 1, cardId = 7 },
}
```

2. `t.test("Draw and Pass accept their exact payload and return a clean copy")` — for each intent,
   drive `Manifest.intents[name].validate(base)`; assert `ok == true` and `deepEqual(clean, base)`.
   This is the **clean control** every case below needs beside it.

3. `t.test("rule 7: no card intent accepts a seat, a pass target or a hand index")` — for each
   intent in `BASES` and each name in `FORBIDDEN_KEYS`, build a copy of `base` with that extra key
   set to `1`, drive `validate`, assert `ok == false` and the code is exactly `"UnknownKey"`,
   with a message naming the intent and the key. Count the cases in `seen` and assert
   `seen == 14` (2 intents x 7 keys) — a hard number, so a renamed intent or a shortened list is a
   failure rather than a quieter test.

4. `t.test("negative control: the forbidden-key checker can tell a tight schema from a loose one")`
   — build a LOCAL `Validate.exactKeys({ seq = ..., seat = ... })` and drive the same loop against
   it; assert it **accepts** `seat` while the real `Draw` schema rejects it. Without this, a bug
   that made every payload fail would make case 3 pass for the wrong reason.

5. `t.test("Draw and Pass reject NaN, infinity and a non-number seq")` — per intent: `seq = NAN`,

6. `t.test("Pass rejects a cardId outside the sanity bound, and 49 is inside it")` — `cardId = 0`,
