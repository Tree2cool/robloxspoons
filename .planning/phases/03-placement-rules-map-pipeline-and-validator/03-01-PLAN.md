<objective>
Bump the map contract to v2: `Node` gains `up`, `canCollide` and `shape`, `CONTRACT_VERSION` goes
1 to 2, both snapshotters emit the new fields identically, and a BasePart-shaped Node missing them
is a build failure under one new stable code.

Purpose: D-02. Phase 1 recorded the gap at `01-07-SUMMARY.md:239` — `Node` carries a look vector
but no up vector, so a roll about the look axis is invisible. The graybox's `Ramp` is built by a
roll about Z, **and a roll about Z does not change the look vector**, so under v1 the ramp
snapshots as a flat floating slab. The ramp is the only route onto the `Ledge`, and 4 of the
graybox's default spots sit on that ledge. Without `up` a correct reachability pass culls all four
and the reference map fails `MIN_DEFAULT_SPOTS = 16`. This is the fix for a wrong answer, not a
tidy-up. `canCollide` (D-03) keeps non-collidable set dressing from inventing standable surfaces or
falsely blocking a sightline.

This plan is the phase's interface-first wave: every later plan builds against Node v2. It
deliberately does **not** re-author the graybox's spot table — that is plan 03-06's work, which can
only be done once `SpoonPlacement` exists to measure each spot. Here the graybox changes only its
`ContractVersion` attribute and its explicit `CanCollide`, so the suite stays green at the end of
this plan.

Output: Node v2, two shape-identical snapshotters, a regenerated v2 `.rbxm`, and the field-by-field
shape-parity gate that must_have 1 demands.
</objective>

**The v2 field contract, enforced by `MAP_NODE_BASIS_INVALID` (this is a STRUCTURAL check, not a
placement one — it runs in the existing whole-tree walk so it fires even when the placement stage
does not):**

| Condition on a Node | Verdict |
|---|---|
| has `position` and `size` and `look` (i.e. it is a BasePart) but `up == nil` | `MAP_NODE_BASIS_INVALID` |
| has `position` and `size` and `look` but `canCollide == nil` | `MAP_NODE_BASIS_INVALID` |
| `className == "Part"` and `shape == nil` | `MAP_NODE_BASIS_INVALID` |
| `className ~= "Part"` and `shape ~= nil` | `MAP_NODE_BASIS_INVALID` |
| `abs(len(look) - 1) > LOOK_EPSILON` or `abs(len(up) - 1) > LOOK_EPSILON` or `abs(dot(look, up)) > LOOK_EPSILON` | `MAP_NODE_BASIS_INVALID` |

`LOOK_EPSILON` is the existing `1e-3` in `MapValidator.luau`; reuse it, do not introduce a second
angular tolerance.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.rbxm` on disk -> `snapshot.luau` | A map file is untrusted input: it may be hand-edited, truncated, or carry a malformed basis. The snapshotter reads properties; the validator is the only thing that judges them |
| live `ServerStorage.Maps.<id>` tree -> `MapLoader.snapshot` | Same data, different reader. A divergence between the two readers is itself the vulnerability |
| map author -> contract version | A v1 map silently accepted would be validated against geometry the rules cannot see |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Tampering | a malformed or hand-edited Node basis (`look`/`up` not orthonormal) silently normalised | mitigate | `MAP_NODE_BASIS_INVALID` with a unit-length and perpendicularity check within `LOOK_EPSILON`; research explicitly forbids normalising silently. Five exact-set-equality fixtures, one per condition. ASVS V5 |
