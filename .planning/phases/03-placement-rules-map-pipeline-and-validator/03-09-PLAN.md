**Winding rule — `MAP_SEAT_ORDER`.** For seats 1 to 9, compute each seat's bearing about the
`TableAnchor` in degrees, clockwise from north with x east and z south:

```luau
	local bearing = math.deg(math.atan2(seat.x - anchor.x, -(seat.z - anchor.z)))
	if bearing < 0 then
		bearing += 360
	end
```

Require every consecutive step, **including the wrap from seat 9 back to seat 1**, to lie strictly
inside `(0, 180)` degrees, and require the nine steps to sum to 360 within `WINDING_EPSILON_DEGREES`.
The two conditions together are what pin the ordering: a step inside `(0, 180)` forbids a backward or
antipodal jump, and the sum forbids a set of seats that winds round twice or not at all. Report
`MAP_SEAT_ORDER` on the **later** seat of a bad step, with a path of `<seats>/Seat<n>`, so a map
author sees which seat is out of place rather than only that the ring is wrong.

**Facing rule — `MAP_SEAT_FACING`.** Require
`dot(horizontal(seat.look), normalise(anchor - seat)) >= math.cos(math.rad(FACING_TOLERANCE_DEGREES))`.

```luau
local WINDING_EPSILON_DEGREES = 1.0
-- 5 degrees, about 0.996 as a dot product. A generated seat (CFrame.lookAt, exact to float32)
-- passes with nothing to spare; a hand-authored Studio seat is allowed human error. Tighter than
-- 5 degrees would make hand authoring in Studio miserable for no gameplay gain; looser would let a
-- seat face the next seat rather than the table.
local FACING_TOLERANCE_DEGREES = 5.0
```

The `look` vector's y component is ignored for the facing test (a seat tilted up or down still faces
the table), but the horizontal direction must be right. State that choice in a comment: the graybox's
seats have `look.y == 0` and the existing graybox case asserts it, so a tilted seat is a map-quality
question for Phase 7a rather than a contract violation here.

**Degenerate seat.** A seat whose horizontal distance to the anchor is below `LOOK_EPSILON` has no
defined bearing and no defined facing direction. Report `MAP_SEAT_ORDER` for it (the ring is
malformed) and **skip** the facing test for that seat rather than dividing by a near-zero length.
That is one of the six fixtures.

**Where it runs.** With the structural card-table pass, where `seats` and `tableAnchor` are already
collected — **before** the sort and before the placement seam. It is structural, so it must fire
even on a map whose geometry is bad, and the placement stage must not run on a map whose seats are
wrong.
</interfaces>
