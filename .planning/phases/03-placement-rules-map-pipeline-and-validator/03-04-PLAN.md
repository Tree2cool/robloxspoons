<objective>
Build the reachability layer: a multi-layer walkable height field over the map's bounds, and an
iterative flood fill from every seeker spawn whose 4-neighbour links are verified by an exact
segment test.

Purpose: D-05, D-06 and D-07. `PathfindingService` is a Roblox API and cannot live in the pure zone,
so choosing it would have forced the two-tier split D-01 rejected; a walkable-grid flood fill is
pure, deterministic, headless and gives the same answer every run. The grid is a **multi-layer**
height field — a 2D lattice of columns, each holding a list of standable heights — because a
single-height 2D grid cannot represent a floor above a floor and would make the mansion
unvalidatable, while a full 3D voxel grid would be about 461,000 mostly-air cells over the graybox
bounds alone. Reachability is measured from **all** seeker spawns, which is the literal requirement:
a seeker starting where seekers start can get there. Not from the hider spawn (the seekers wait in a
closed parkour room, so the hider's region answers the wrong question) and not "any largest
connected region", which stops catching the real bug.

Two findings from research shape the implementation and neither is obvious:

**Erosion must carry a slope allowance.** The naive rule "drop a cell if any neighbour within
`CAPSULE_RADIUS` has a solid above `h + STEP_UP`" **erodes the walkable slope itself**: on a ramp the
neighbour `capR` away is `capR * tan(slope)` higher. Measured, that makes the ramp require
`STEP_UP >= 1.5 * tan(24.9) = 0.696` instead of `1 * tan(24.9) = 0.464`, so the config invariant
plan 03-02 locked would silently stop protecting anything.

**Grid-only links leak through thin walls, and the leak direction is the dangerous one.** Measured on
a 0.3-thick full-width wall: with grid-only links **all 1,600 cells read as one region** — the wall
was invisible — while an exact segment test between each linked pair at two body heights reached 840.
A leak means a sealed spot is marked reachable and an unfindable spoon ships.

Output: `src/server/core/WalkGrid.luau`, the shared `MicroWorld` fixture set that later plans build
corpus cases from (including D-19's over-a-void pit, which the graybox cannot express), and a spec
whose ramp case has a negative control.
</objective>

```luau
--!strict
local MapContract = require("./MapContract")
local Obb = require("./Obb")

type Vec3 = MapContract.Vec3
type Aabb = MapContract.Aabb
type Box = Obb.Box

-- Deterministic work counters. They exist so a time-cap gate can prove the bake DID something
-- before it reads a clock (research D-09): a cap on an empty bake passes vacuously.
export type Counters = {
	boxes: number,
	columns: number,
	spans: number,
	cells: number,
	reached: number,
	linkTests: number,
	eroded: number,
}

-- A multi-layer walkable height field. Flat parallel arrays; cell c belongs to column
-- colOf[c], and a column's cells occupy colFirst[idx] .. colFirst[idx] + colCount[idx] - 1,
-- ascending in height. idx = j * nx + i + 1.
export type Grid = {
	gridSize: number,
	originX: number,
	originZ: number,
	nx: number,
	nz: number,
	colFirst: { number },
	colCount: { number },
	colOf: { number },
	cellX: { number }, -- cell centre x
	cellZ: { number }, -- cell centre z
	cellH: { number }, -- standable floor height (the span top)
	cellCeil: { number }, -- the next solid above it, or bounds.max.y
	region: { number }, -- 0 = not reached from the seeker spawns, 1 = reached
	counters: Counters,
}

export type GridConfig = {
	GRID_SIZE: number,
	STEP_UP: number,
	MAX_SLOPE_DEGREES: number,
	CAPSULE_RADIUS: number,
	CAPSULE_HEIGHT: number,
}
```

Exported functions, exact signatures:

```luau
WalkGrid.columnCountFor(bounds: Aabb, gridSize: number) -> number   -- cheap, bounds-only, for the bake-size ceiling
WalkGrid.build(boxes: { Box }, bounds: Aabb, config: GridConfig, index: Obb.Index) -> Grid
WalkGrid.flood(grid: Grid, boxes: { Box }, index: Obb.Index, seeds: { number }, config: GridConfig) -> ()
WalkGrid.seedsAt(grid: Grid, point: Vec3, dropLimit: number) -> { number }
WalkGrid.columnIndexOf(grid: Grid, x: number, z: number) -> number?
WalkGrid.cellsNear(grid: Grid, x: number, z: number, radius: number, out: { number }) -> number
```

**Grid origin (research, and it matters for reproducibility):** anchor to the **world** lattice,
`originX = math.floor(bounds.min.x / gridSize) * gridSize` and likewise for Z, **not** to
`bounds.min` itself, so cell edges coincide with Studio's integer snap grid. Cells whose centre falls
outside `bounds` are discarded. Ledge connectivity on the graybox held for origin shifts of 0, 0.1,
0.25, 0.37 and 0.5 at both g=1 and g=2, so the answer is insensitive to alignment on that map;
anchoring to the world lattice is still the right default because it is the one a map author can
predict.

**Erosion rule, exact (Pattern 2):** a neighbour column at horizontal distance `d` blocks cell `c`
only when `neighbourSpan.hi > cellH[c] + STEP_UP + d * tan(MAX_SLOPE_DEGREES)` **and**
`neighbourSpan.lo < cellH[c] + CAPSULE_HEIGHT`. With that allowance the minimum workable `STEP_UP`
falls back to exactly `GRID_SIZE * tan(slope)`. **Do not erode away from drop-offs** — Recast does,
and we must not, because a ledge spot 2 studs from an edge and a seeker standing at a shelf edge are
both real cases. Only obstructions above `STEP_UP` erode.

**Link conditions, all three required (Pattern 3):** for a 4-neighbour pair of cells `c` and `n`,
1. `math.abs(cellH[n] - cellH[c]) <= STEP_UP`
2. `math.min(cellCeil[c], cellCeil[n]) - math.max(cellH[c], cellH[n]) >= CAPSULE_HEIGHT`
3. no box intersects the centre-to-centre **segment** at either of two body heights:
   `math.max(cellH[c], cellH[n]) + STEP_UP + 0.25` and
   `math.max(cellH[c], cellH[n]) + CAPSULE_HEIGHT - 0.25`
Every evaluation of condition 3 increments `counters.linkTests`.

**4-connectivity only.** 8-connectivity allows diagonal leakage through corner gaps and complicates
the corner-clearance proof; 4-connectivity is sound and conservative for reachability.

**No recursion.** Luau has a call-depth limit and a long corridor exceeds it. One array queue with
`head`/`tail` indices. The maze fixture in plan 03-07 exists partly to catch a recursive
implementation.

**`build(boxes, bounds, config, index)`** — the bake, in the order research specifies:
1. Compute `originX`, `originZ` by the world-lattice rule, then `nx`, `nz`. Pre-size `colFirst` and

2. Per column, query the bucket index for boxes whose AABB covers the column's XZ centre, call

3. Sort and merge the intervals into spans. **Only sort columns with more than one interval** — the
   sort is the bake's hot spot.
4. A span top is a **floor candidate** when `nyTop >= cosine(MAX_SLOPE_DEGREES) - 1e-4`, where
   `cosine` is precomputed once outside the loop. The ceiling above it is the `lo` of the next
   interval, or `bounds.max.y` when there is none. Keep the candidate only when
   `ceiling - top >= CAPSULE_HEIGHT`. Increment `counters.spans` per merged span and
   `counters.cells` per kept candidate.
5. **Erosion**, exactly as the `<interfaces>` formula states, over neighbour columns within
   `CAPSULE_RADIUS`. Increment `counters.eroded` per dropped cell. Add the comment that we do not
   erode away from drop-offs and why.
6. Discard cells whose centre falls outside `bounds`.
7. Fill the flat arrays in column-major order so `colFirst`/`colCount` index them contiguously and
   each column's cells ascend in height. Initialise `region` to all zeros.

**`flood(grid, boxes, index, seeds, config)`** — transcribe research's iterative BFS. One array
queue with `head`/`tail` integers, no recursion, no `pairs` over a hash. For each popped cell, for
each of the four XZ neighbours, for each cell in that neighbour column not already in `region`,
evaluate the three link conditions in the `<interfaces>` order (cheapest first: height difference,
then shared headroom, then the two segment tests). Set `region[n] = 1`, push, and increment
`counters.reached`. Increment `counters.linkTests` on every evaluation of condition 3.

**`seedsAt(grid, point, dropLimit)`** — the cells in `point`'s column whose height is at or below
`point.y` and no more than `dropLimit` below it, nearest first. Returns an **empty array** when
there is none; the caller (plan 03-05) turns that into a loud issue. Comment: *Pitfall 10 — if no
spawn finds a cell the BFS runs on an empty queue and reports 0 reached, and every spot then fails
with a misleading reason. An empty return here is the signal, and it must never be treated as "flood
everything".*

**`columnIndexOf(grid, x, z)`** — `nil` when outside the lattice.

**`cellsNear(grid, x, z, radius, out)`** — append the indices of every cell in every column whose
centre lies within `radius` horizontally, into the caller-supplied `out`, and return the count. At
`GRID_SIZE` 1 and `PICKUP_RANGE` 7 that is about 200 columns, which is the budget Pattern 4 sets for
the per-query cost. Allocate nothing per call.

**Determinism and performance:** flat parallel arrays beat tables of tables; pre-size with
`table.create(n)`; hoist `math.abs`, `math.min`, `math.max`, `math.sqrt` into locals in the hot
loops; precompute `math.cos(math.rad(MAX_SLOPE_DEGREES))` and `math.tan(math.rad(...))` once; iterate
arrays in index order only.
