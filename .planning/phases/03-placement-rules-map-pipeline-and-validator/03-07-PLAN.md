<objective>
Build Gate G2's stress fixture: a Lune-generated synthetic adversarial maze with a **known answer**,
and the spec that holds the bake to a wall-clock cap.

Purpose: D-08 and D-09. The maze is **an oracle first and a stressor second**, and getting that
ordering right is the whole design. Research measured a 240 x 240, 4-level, 4,640-box maze baking in
0.38 s and flooding in 0.036 s at the shipped resolution, and explains why: bake cost is
`O(sum over boxes of covered columns) + O(columns x spans)` while flood cost is
`O(reached cells)` and path length does not affect a queue at all. **A maze is therefore not a time
stressor for BFS.** What it adds is correctness pressure — long single-width paths (queue depth, and
a recursive implementation's call-depth limit), dead ends, many thin walls, a deliberately sealed
region, and above all a set of cell centres whose reachability is known in advance.

**The trap this fixture must not fall into.** Measured: at corridor width 3 with `CAPSULE_RADIUS`
1.5 and `GRID_SIZE` 1, erosion leaves **zero** reached cells, while widths 4, 5 and 6 reach all
`N^2` maze-cell centres. A fixture that asserts only "the sealed region was not reached" is
therefore **trivially true** at width 3 and reads green while testing nothing. The oracle must
assert the positive half first, and the generator must refuse a corridor narrower than
`2 * CAPSULE_RADIUS + GRID_SIZE`.

The real maze map (MAP-08) is Phase 7a work. This fixture gives its author a performance target to
stay under, and it gives this phase the "maze bake stress test completes" half of Gate G2.

Output: a parameterised generator with a sidecar oracle, and a spec whose every assertion has been
watched fail.
</objective>

**CLI:**

```
lune run scripts/maps/generate-maze.luau [outputPath] [--footprint N] [--corridor N]
    [--wall N] [--levels N] [--braid F] [--sealed N] [--thin N] [--seed N]
```

Default `outputPath` is `build/maze.rbxm`. The generator **also** writes an oracle sidecar beside it
at `<outputPath>.oracle.json`, and prints one summary line.

**Dials and defaults (research's table):**

| Dial | Default | What it stresses |
|---|---|---|
| `footprint` | 248 | bake columns (248 x 248 at g=1 is 61,504 columns) |
| `corridor` | 6 | box count; **refuse `corridor < 2 * CAPSULE_RADIUS + GRID_SIZE`** |
| `wall` | 1 | thin walls, and box count |
| `levels` | 4 | layers per column; stacked slabs 24 studs apart |
| `braid` | 0 | 0 = perfect maze (one path, longest dead ends); above 0 knocks extra walls out |
| `sealed` | 1 | sealed pockets holding default spots, to prove the cull fires |
| `thin` | 1 | one 0.3-thick full-width wall, to prove link verification |
| `seed` | 20261104 | reproducibility |

**Determinism: use an integer LCG, not `math.random`,** so the emitted bytes are stable across Lune
versions and the spec can compare them. Write the LCG inline (about six lines) with the constants in
a comment; do not require `src/server/engine/Rng.luau` — that is shipped code and a script requiring
it is fine, but the bytes must not change if that module is ever tuned, so a local LCG is the
decoupled choice. Say that in a comment.

**Oracle sidecar, exact shape** (written with `@lune/serde`'s `encode("json", ...)` or a small
hand-rolled writer — either is fine, but it must be valid JSON a spec can decode):

```json
{
  "seed": 20261104,
  "footprint": 248,
  "corridor": 6,
  "wall": 1,
  "levels": 4,
  "gridSize": 1.0,
  "capsuleRadius": 1.5,
  "open":   [ { "x": 0, "y": 0.5, "z": 0 }, ... ],
  "sealed": [ { "x": 0, "y": 0.5, "z": 0 }, ... ],
  "spotsInSealed": [ "Spot07" ]
}
```

`open` holds the centre of every maze cell on level 0 that the generator carved as reachable from
the spawn cell. `sealed` holds the centre of every cell inside a sealed pocket. The two sets are
disjoint and together cover every level-0 maze cell. `spotsInSealed` names the authored default
spots the generator placed inside a pocket.

**The map is contract-shaped** so the same fixture serves plan 03-08's CLI integration case: a
`Model` root with `ContractVersion = 2`, `DisplayName`, `MinPlayers = 3`, `MaxPlayers = 10`,
`SizeClass = "Large"`; a `Geometry/` folder with the floors, walls and level slabs; and a `Data/`
folder with `Bounds`, `HiderSpawn`, `SeekerSpawns/` (one spawn at a level-0 open cell centre),
`DefaultSpots/` (at least `MIN_DEFAULT_SPOTS` spots, of which `sealed` many sit inside pockets),
`DecoyAnchors/` (empty is legal) and `CardTable/` with `TableAnchor` and `Seat1` to `Seat9`. Author
the seats on a radius-6 ring at 40-degree spacing oriented by `CFrame.lookAt` at the anchor, exactly
as the graybox generator does, so plan 03-09's seat-winding check passes on this map too.

**The generator must refuse an invalid corridor** with a non-zero exit and a message naming the
computed minimum:

```
generate-maze: corridor 3 is below the minimum 4 (2 * capsuleRadius 1.5 + gridSize 1.0);
  erosion would leave zero walkable cells and every reachability assertion would pass vacuously
```

That refusal is itself a tested behaviour: the spec asserts the exit code and the message. It is how
Pitfall 4 is prevented at the source rather than only detected downstream.

Implementation:

1. **Argument parsing.** `outputPath = args[1] or "build/maze.rbxm"` when `args[1]` does not start
   with `--`; then `--key value` pairs for the eight dials. Tolerate a bare `--` separator the way
   `validate-map.luau` does (Lune 0.11.1 passes it through). An unknown flag is a non-zero exit with
   a usage line — a typo in a dial must not silently run the defaults.

2. **The corridor refusal**, before anything is built: compute
   `minimum = 2 * CAPSULE_RADIUS + GRID_SIZE` from literals duplicated in this file (1.5 and 1.0,
   with the comment that they are duplicated on purpose and that
   `tests/placement/config_lock.spec.luau` is where the shipped values are locked), and
   `process.exit(1)` with the exact message from `<interfaces>` when `corridor < minimum`.

3. **The LCG.** `state = (state * 1103515245 + 12345) % 2147483648`, returning
   `state // 65536 % bound`. Constants in a comment.

4. **Maze carving.** A standard iterative depth-first carve over an `n x n` lattice of maze cells
   where `n = footprint // (corridor + wall)`, using an explicit stack (not recursion — the script
   is allowed recursion but the shape should mirror the flood's discipline). `braid` above 0 knocks
   out that fraction of remaining walls after carving, chosen by the LCG.

5. **Sealed pockets.** Pick `sealed` maze cells far from the spawn cell, and **re-wall** every
   opening into them so they become disconnected. Record their centres in the oracle's `sealed`
   array and every other level-0 cell centre in `open`. Assert internally (a `assert` in the script)
   that the two arrays are disjoint and that their union covers every level-0 cell — a generator
   whose own oracle is wrong is worse than no oracle.

6. **Levels.** `levels` stacked copies of the carved maze, each 24 studs above the last, as separate
   floor slabs with their own walls. **Only level 0 is linked to the spawn**; the other levels are
   intentionally unreachable and their cells still count toward bake cost. That is what makes the
   fixture a bake stress rather than a flood stress — say so in a comment.

7. **Thin walls.** `thin` full-width walls of thickness 0.3 placed across level 0 at positions the
   LCG chooses, each sealing off a strip. Each strip's cells go into `sealed`. This is the link
   verification case at maze scale.

8. **The contract-shaped `Data/` folder**, exactly as `<interfaces>` specifies, reusing the graybox
   generator's `anchor`/`anchorAt` helpers and its seat ring. Place `MIN_DEFAULT_SPOTS + 2` default
   spots at open-cell centres plus one spot per sealed pocket, and name the sealed ones in
   `spotsInSealed`. `Bounds` must cover the whole footprint and every level with a stud of slack.

9. **Write both files** and print:
   `generate-maze: wrote <path> (<bytes> bytes, <boxes> boxes, <open> open cells, <sealed> sealed cells) and <path>.oracle.json`

The default run must land near research's measured figures. If the box count comes out far from
4,640 at the defaults, record the actual number in the summary rather than tuning the dials to hit
the research figure — the cap is set from the measured time, not from the box count.
